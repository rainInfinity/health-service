# Design

## Context

动机及范围见 `proposal.md`。当前 `health_inference` 通过 `AlgorithmDefinition.run()` 校验必需输入、参数和结果，再调用显式注册的 `runner`；`health_service.infrastructure.inference_adapter` 按 `ModelVersion.id` 缓存算法定义、固定参数和制品存储键，并提供按任务及执行令牌隔离的输出目录。保留这两个现有边界，不增加第二套业务执行入口。

旧算法参考实现为相邻项目 `../nxhe-backend/src/models/services/hr_br/main.py`、该目录的 `utils/ppg.py` 及 `src/models/utils/process.py`。本仓库独立运行时不得依赖相邻项目路径。旧实现把输出路径存到模型实例上、通过上传路径替换推导输出位置，并在 BR 为 NaN 时返回 `12`；这些行为不能照搬。现有 `hr_br.example` 是无第三方运行依赖的真实输入诊断，必须保持其 key 和行为。

开发规范已先更新至 `docs/development/models-and-algorithms.md`。本设计将其中的目标架构落到正式 v1，而不是宣称模板已经实现。

## Goals / Non-Goals

**Goals:**

- 在已有契约入口内实现模板方法，算法仅提供阶段实现和策略，不重复编排阶段。
- 质量检测和后处理可替换，预处理与推理分别成模块；阶段间使用有明确类型的数据，不恢复旧通用可变字典。
- 同一进程内实现修订、模型发布版本及不同任务相互隔离，Web 不加载科学计算依赖。
- 正式输入失败原因在任务详情中可辨认，同时保持固定错误码和安全文案边界。

**Non-Goals:**

- 不实现通用 DAG、插件发现、运行时动态代码导入、实时流处理或新任务状态。
- 不改变现有队列、租约、恢复、事务、渠道选择、文件授权或缓存释放语义。
- 不为诊断示例伪造质检或推理阶段，不新增全局评分、合理范围或输入修复算法。

## Decisions

### 1. 在现有契约内部增加离线模板，而不是取代注册机制

`AlgorithmDefinition.run()` 保留必需文件、资料、参数和输出契约校验。新增 `OfflineAlgorithm` 的统一 `run()` 固定阶段顺序：`load_input()`、`preprocess()`、质量策略、`predict()`、后处理策略、`build_output()`。具体实现不覆写该阶段调度入口；声明方法和泛型阶段类型，使输入、预处理数据和预测结果能够被静态检查。

质量策略或后处理策略不适用时，必须显式声明未执行；模板不得用默认满分或空策略冒充执行过。正式 HR/BR v1 两项均执行。第一次失败直接抛出已有契约异常，不为收集更多原因继续执行，也不统一捕获异常后改成输入错误。成功文件只在门禁、推理和后处理完成后生成。

质量策略返回实际质量信息，拒绝时抛出已有 `QualityRejectedError`；不强迫没有评分的其他算法伪造评分。后处理策略接收原始预测并返回最终预测。不同算法仅在规则确实相同时复用具体策略，不因同为 HR/BR 输出就共享阈值。

备选是每个 runner 自行组织阶段，容易出现低分仍预测和输出组织先于后处理；另一备选是所有阶段策略化并允许自由排列，增加了本次不需要的配置复杂度。因此只对已经明确需要替换的质量与后处理建立策略接口。

### 2. 完整实现标识与平级版本目录

正式实现固定为 `ppg.active.offline.hr_br.v1`，其目录为：

```text
health_inference/
+-- pipeline.py
+-- strategies.py
+-- types.py
+-- exceptions.py
+-- quality.py
+-- registry.py
+-- algorithms/
    +-- __init__.py
    +-- ppg_active_offline_hr_br_v1/
        +-- __init__.py
        +-- algorithm.py
        +-- input.py
        +-- preprocessing.py
        +-- quality.py
        +-- inference.py
        +-- postprocessing.py
```

`algorithm.py` 声明算法契约、装配策略、实现阶段衔接和组织输出；`input.py` 读取校验；`preprocessing.py` 提取与清洗；`quality.py` 实现本版本评分；`inference.py` 只做原始估计；`postprocessing.py` 只执行已确认的后处理。阶段结构就近定义，不新增只转发名称的类型模块或公共工具目录。

未来 v2 平级放在 `ppg_active_offline_hr_br_v2/`，本次不创建它。注册表仍使用已有 key 查找，不增加算法版本数据库字段，不根据模型发布版本字符串推断代码位置，不注册 `latest` 或无版本 key。代码中需要保留的旧行为必须保留对应实现；模型版本继续冻结参数与制品。移除失效的 `hr_br/template.py` 及模板结构测试，不保留兼容别名；现有示例保留原目录和契约。

备选的四段目录嵌套或独立 `v1/` 层均不采用：用户已确定完整名称加版本后缀，平级目录与 key 直接对应。

### 3. v1 固定单块输入，不引入采集补救或新的调参面

输入逻辑名为 `ppg`。使用 UTF-8 CSV，兼容 BOM；要求唯一表头、`timestampFrame` 和且仅一组完整 RGB 或 YUV 通道。时间戳与所用通道必须是有限数值，时间戳严格递增。附加相机列可忽略，不要求 `frame.csv`、运动数据、健康资料或客户端元数据。

没有 `blockIndex` 的旧单块数据允许进入；存在时必须是整数 `0`。非零、非法块编号或重复帧时间戳不得被选块、去重或聚合。`frameIndex` 不是估计必需字段，不以请求 FPS 或帧序号替代时间轴。

采样率沿用旧时间差均值的计算与两位小数表示；不新增采样不均匀度阈值，不重采样。数据条数、采样率和可标准化条件只检查实际处理所需前提，例如滤波填充长度、Nyquist 条件和非零标准差；不另设未经确认的最短采集秒数。明确不满足时报告受控输入错误。不得通过广泛捕获第三方 `ValueError` 将程序错误掩盖成输入问题。

v1 不接受改变算法含义的固定参数，空参数映射有效，非空参数拒绝；质量阈值 `70`、BR 上限 `18` 作为该实现的固定规则。将来需要参数化时必须明确兼容性和发布契约，不在本次顺带引入可调滤波或融合参数。

备选是固定块选择或融合，用户已选择本次只接受单块。这个限制必须在具体算法文档和普通任务错误中明确，而不能仅藏在解析器里。

### 4. 迁移数值链，质量门禁先于估计

- RGB 取 `-avgR / 255`；YUV 沿用 BT.709 转换，使用 `-(avgY + 1.5748 * (avgV - 128)) / 255` 形成 PPG。完整通道组仍按输入契约校验，不对通道另加裁剪。
- 心率信号使用二阶 Butterworth `0.75–4 Hz` 带通、`filtfilt` 和 Z-score；呼吸信号使用同阶 `0.1–0.5 Hz` 带通及标准化。复用原始提取信号，不重复读文件。
- 质量策略调用与旧版一致的 PPG 质量评价，均值乘以 `100`，保留实际比较值；分数小于 `70` 时报告 `LOW_SCORE`。不新增 `NO_VALID_SIGNAL` 判据，也不将非法评分改成默认值。
- 推理阶段沿用 `ppg_findpeaks`、`ppg_rate` 与 `rsp_rate` 的旧调用方法，速率均值形成原始 HR/BR；NeuroKit 的采样率参数沿用旧版 `int(fs)`。不在迁移中更换峰检测或呼吸估计方法。
- 后处理先验证两个原始数值均有限，再对 BR 执行 `min(br, 18)`，HR 保持原值。不增加下限或四舍五入，不做 NaN/无穷值替换。

用户已明确选择：保留 BR 上限，无效 HR/BR 报结果错误；不是原样保留 NaN 补 `12` 的旧行为。先做有限性检查可以防止正无穷 BR 经截断变成看似正常的 `18`。

探索阶段已用旧环境的 NumPy 2.3.5、SciPy 1.16.3、pandas 2.2.3 和 NeuroKit2 0.2.12 只读运行合成信号处理链：60 秒、30 Hz、心率分量 72 的单块输入，呼吸分量 12 时旧链 HR 约 72.5656、BR 约 12.1356；呼吸分量 24 时原始 BR 约 24.0983，最终截为 18。逐帧重复行后仍可能通过评分且 BR 失真，因此不能靠评分替代块布局检查。这些仅是迁移基线证据，不是新实现已通过验证，也不是医学准确性证据。

### 5. 受控输入原因与服务端映射一并落地

在现有 `exceptions.py` 中增加类型化输入错误与受控原因，保留错误码 `INFERENCE.INVALID_INPUT`；不放到质量拒绝体系，也不新增数据库字段。最小原因集合覆盖 CSV 格式、缺列、通道、非有限数值、时间轴、块布局、数据不足与无效采样率。服务端在 `application.execution._safe_failure_fields()` 中验证原因后映射固定安全文案，普通失败的 `failure_detail` 仍为空。

例如块布局映射为“当前算法版本仅支持单块 PPG”，时间轴映射为“PPG 时间戳必须为有限且严格递增的毫秒数值”。现有普通 `InferenceError`、未知或损坏原因继续使用通用输入失败摘要；不以异常消息作为公开文案来源。非法预测继续使用 `RESULT.INVALID_OUTPUT`，质量拒绝仍走已有白名单路径。

备选是直接传递 `safe_message`，但当前运行时有意丢弃任意错误正文，这样修改会破坏现有安全边界。类型化原因与白名单映射能让用户分辨输入问题，又不放开异常透传。

### 6. 输出、依赖和加载生命周期

v1 成功载荷为 `hr`、`br` 与 `quality`；`quality` 包含实际执行得到的 `score` 和固定 `threshold`，不补默认质量通过。可投影指标代码为 `hr`、`br`，单位沿用旧模板的 `beats_per_minute` 和 `breaths_per_minute`。最终值先转换为原生有限浮点数，payload 与 metrics 使用同一份后处理结果，不把原始估计单独投影。

在本次 `output_dir` 内写 `ppg-processed.csv` 和 `rsp-processed.csv`，对应逻辑名 `processed_ppg`、`processed_rsp`。列分别为 `timestamp,ppg` 和 `timestamp,rsp`；时间使用原始 `timestampFrame` 的毫秒值，每行对应输入采样。路径不进入载荷，由既有适配器验证并登记到受保护的输出下载引用。

在 `health-inference` 增加 `ppg` 可选依赖项，直接声明实际使用的 NumPy、SciPy、NeuroKit2；CSV 读写沿用标准库，不为旧 DataFrame 写法新增直接 pandas 依赖。NeuroKit 的传递依赖仍通过单一 `uv.lock` 锁定。优先以上述已运行的旧环境版本作为数值对照起点，在 Python 3.13 下实际解析和运行后确定锁定结果，不仅凭版本号宣称兼容。

注册定义、模板和策略接口不在顶层导入可选库。轻量 runner 只在实际执行时装配具体阶段和策略，并委托统一模板；该入口不得再次调度各阶段。模板实例与策略不保存本次任务数据，现有版本缓存不需要改成存放可变算法任务对象。缺少可选依赖时不能用示例回退为成功，推理部署需按文档显式安装。

### 7. 以消费者可见行为验证，而不是验证目录或转发关系

保留可长期复用的真实计算、拒绝边界和版本隔离测试，删除旧模板结构断言，不把它们重新固定到新目录。单元测试放在 `tests/unit/inference/hr_br/`；跨模块流程扩展现有 `tests/integration/workflows/`，发布规则复用 `tests/integration/catalog/`。不为每个阶段转发写 mock 回显测试。

数值验证使用确定性合成样本及明确容差；固定时间轴和随机种子，覆盖不同心率输入、可估计呼吸分量及 BR 截断。质量比较、非有限值处理和失租等难以稳定由自然信号触发的边界可在对应纯策略或已有持久化边界隔离测试，不依赖随机噪声碰巧失败。

除测试外，实施时实际运行：独立计算调用；仅 Web 环境导入与启动；一次正式版本的创建、发布、选择、文件上传、任务提交、`run_inference --once`、详情查询及两个输出下载；再用多块或低质量输入观察受控失败且无成功投影。使用隔离测试数据和显式批准的运行环境，不改用户真实渠道选择。临时验证脚本和数据完成后清除，长期样例不含真实健康资料。

## Risks / Trade-offs

- [BR 大于 18 的真实估计被截断] → 这是用户确认的 v1 后处理，文档明确上限与适用边界，不把截断结果当作准确性证明；未来改变规则使用新实现修订。
- [旧代码先把非有限输入替换为零，迁移后明确拒绝] → 输入、评分和结果分别校验，保留安全原因；不依赖旧异常或补值行为掩盖失败。
- [客户端已支持多块，而 v1 仅支持单块] → 具体算法文档明确单块要求，多块任务显示专门错误，不静默聚合或选块。
- [科学计算库升级影响数值] → 共用锁文件、旧链对照和行为容差；实现版本隔离不等价于跨环境位级复现。
- [共享模板未来改变旧修订行为] → 模板不含数值规则；维护门禁和阶段数据隔离行为。若模板语义发生不兼容变化，保留旧行为而不是让所有修订自动改变。
- [用户可见错误扩大信息泄漏面] → 仅公开受控原因对应文案，旧错误和未知原因安全降级，不保存任意异常正文。
- [可选依赖使部署漏装后失败] → 文档提供明确安装和独立执行命令，验证 Web 无计算依赖仍可启动；不使用假计算或示例回退。

## Migration Plan

1. 开发规范已先行更新；随后在本变更中实现模板、策略、受控输入原因和 v1，各项实现任务保持未完成直到 apply。
2. 更新计算成员可选依赖和唯一锁文件，补充算法输入、后处理、指标与输出说明；移除旧未实现模板，保留现有示例行为。
3. 在隔离环境完成单元、跨模块及实际运行验证。正式部署先安装计算可选项并部署同时保留旧已注册实现的代码，再由管理流程发布正式 v1。
4. 是否将真实渠道切换到正式 v1 属于外部状态操作，执行前另行确认；本提案和实现不自动替换用户渠道选择。
5. 回退时将渠道重新选择为仍保留的已发布版本，遵守既有草稿终止和已提交任务固定版本规则。仍有渠道或未终结任务引用的实现与制品不能删除；不能把仍需执行 v1 任务的消费者回退到未注册 v1 的代码。无需数据库回滚或删除历史结果。
