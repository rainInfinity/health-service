# Design

## Context

动机与范围见 proposal.md。旧实现位于 `../nxhe-backend/src/models/services/bp/`：`main.py` 组织双模型预测，`utils/ppg.py`、`scg.py`、`ptt.py`、`svmd.py` 定义数值规则，`src/models/utils/process.py` 提供采样率与标准化。它依赖共享可变任务状态，并在质量门禁前写输出文件，不宜直接作为新项目运行时复用。

当前计算包已有 `OfflinePipeline`、版本资源工厂、显式算法注册和 PPG CSV 解析；任务快照已包含 `age_years`、`height_cm`、`weight_kg`、`gender`。`AlgorithmRuntime` 要求可投影数值有限，服务已有质量拒绝、失败映射与受保护文件下载。只有新增血压规则需要增量规格，不修改这些通用契约。

候选来源为 `var/old-assets/` 下三个血压制品和 `sample/` 中的 PPG、ACC 文件。只读统计显示 PPG 929 行、约 30 Hz，ACC 6305 行、约 210 Hz；尚未运行模型，尚不能报告数值对齐。涉及新依赖、可执行制品与多传感器计算，因此需要本设计。

实施顺序已确认：先完成 `reorganize-file-storage-paths` 的实现及验收，再实施本变更。血压实施开始前须核对该前置变更的任务完成情况与实际验收证据，不能把规划产物齐全视为实现完成；若其已归档，读取归档产物和同步后的主规格。血压复用其最终存储接口，不重建旧写入分支或自行实现发布恢复。

## Goals / Non-Goals

**Goals:**
- 将旧版可执行数值解释固定为独立 v1，同时使用当前任务生命周期与版本资源隔离。
- 精确区分缺失补零、已计算非法值、质量拒绝及执行异常，不用新增医学规则改变预测。
- 提供可复核的旧源码、制品哈希、依赖环境、特征和预测对照记录。

**Non-Goals:**
- 不修正旧算法的峰值定义、IQR 严格边界、PR 整数化、资料补零或零 SCG 回退，不新增重采样、传感器时钟校准、SCG 质检或推理参数。
- 不复用旧接口、数据库或路径替换逻辑，不引入模型格式转换、通用沙箱平台或可配置工作流。
- 不修改现有算法、存储重组变更或客户端采集行为。

## Decisions

### 1. 新增独立实现，不包装旧服务对象

新增 `ppg_acc_active_offline_bp_v1/`，按既有模式组织 `algorithm.py`、`load_input.py`、`preprocessing.py`、`quality.py`、`inference.py`、`resources.py`、`build_output.py`，PTT 与 AO 重建放在该实现内的职责模块。真实共用的 PPG 解析复用 `utils/ppg_input.py`；血压数值规则不因看似相似而调用会变化的其他算法私有模块。

运行时只缓存当前版本的两个模型和归一化参数；波形、资料、质量、峰、特征及文件路径均为调用内类型化数据。相比直接复用 `BpModel`，这避免旧 `processed_ppg_url` 等字段污染下一任务。

### 2. 固定输入与资料映射

声明 `required_inputs=(ppg, acc)`，后缀均为 `csv`；PPG 沿用共享的单块 RGB/YUV 输入约束。ACC 使用毫秒 `timestampEvent` 和 `accX,accY,accZ`，其中信号取 `-accZ`。输入要求必需列、有限数值、严格递增时间轴及足够执行滤波的数据；不自动排序、插值、对齐或补齐。两个传感器直接使用原始毫秒时标配对；不能各自减去起点导致相位关系改变。缺列、非法采样或无法执行报告受控输入失败，不伪造质量拒绝。

读取提交快照而非实时资料：`age_years -> age`、`height_cm -> height`、`weight_kg -> weight`、`gender -> sex`，将现有十进制字符串转换为旧计算所用数值。`required_profile_fields=()`，防止通用检查提前拒绝旧版允许缺失的资料。年龄、身高、体重缺失时保留零值路径；常规快照性别未知为 0，男 1、女 2 原样进入 sex，不新增 one-hot 或性别缺失补值规则。直接调用若缺少 sex，不把旧版的 None 静默改成其他值，无法预测时按执行失败终止。

### 3. 固定计算解释与门禁位置

PPG 保留负红通道/旧 BT.709 转换、二阶 0.75–4 Hz 带通和 z-score；ACC 保留旧二阶 1–25 Hz 带通的采样率边界与 z-score。采样率按旧 `calc_fs` 的两位小数规则计算，不改用共享解析器的未舍入结果代替。PPG 质量使用旧计算和 int(fs)，平均分乘 100，阈值固定 70。

流水线预处理准备清洗波形，质量策略立即执行门禁；AO 重建、峰配对与特征准备放在门禁后的推理阶段。旧版在 preprocess 内提前完成这些工作，但对通过门禁的数值无影响；新位置满足现有流水线约束，低分时不继续重计算或提前写成功文件。

SCG 保留顺序 VMD 的固定参数和残差能量停止条件，AO 使用 8–24 Hz 与波形因子双条件；交集为空时回退频率条件，仍无模态时返回零信号。保留 VMD 长度变化时的旧截断行为，输出 SCG 对应截断后的时间轴。不得为“优化”额外增加模态上限或改停止条件；现有任务执行超时机制保持不变，其实际终止能力须在运行验证中核实。

PPG 峰保留对 `-cleaned_ppg` 检测、最大 120 bpm、prominence 0.6；AO 保留 400 ms 搜索窗口，配对为峰前 50–500 ms 取最近候选。PTT 按严格 IQR 边界过滤、取绝对均值并保留六位小数。无配对返回 None 后按旧 `or 0` 补零；IQR 清空产生 NaN 时仍为 NaN，不补零、不扩大筛选边界。PR 为峰数除以向上取整的 PPG 秒时长，再转 int。

特征顺序固定 `[PTT秒, age, pr, bmi, height米, sex]`；前五项按 CSV 的 `miu`、`segma` 标准化，sex 原样保留。空参数表示全部规则固定，拒绝任何非空参数。

### 4. 保留 joblib，明确可信边界

制品逻辑名为 `sbp`、`dbp`、`normalize`，后缀分别为 `joblib`、`joblib`、`csv`。版本资源加载器只加载绑定路径，不扫描目录或跟随 latest 文件名选择版本。两个模型须能处理六维输入，各返回一个数值；归一化 CSV 须包含 X1、age、pr、bmi、height 的 miu 与有限非零 segma，不兼容制品按 `INFERENCE.INVALID_ARTIFACT` 失败，不用默认权重。

`var/old-assets/` 仅用于迁移来源核验和隔离数值对照，不能作为正式版本的运行资源目录。正式制品通过已有上传入口登记到存储重组后的 `<model_code>/<version>/<logical_name>-<uuid.hex>.<ext>`，执行只使用该版本已登记并解析的路径。输入同样沿用前置变更按任务创建时间、渠道及身份生成的存储键，算法不解析上传文件名推断业务信息。

选择保留原格式而非转 ONNX，避免在迁移时引入预测解释差异。joblib 加载可能执行代码，类型和维度检查发生在反序列化之后，不能作为安全屏障。部署前必须核验来源和哈希，仅允许受信发布人员上传经确认的内部制品；当前 manager 授权是权限边界，不是沙箱。本变更不承诺安全执行不可信模型。首次候选加载与兼容验证应在无业务凭据的隔离环境执行。

依赖从旧声明 `pygam==0.12.0`、`vmdpy==0.2` 开始，与当前锁定科学计算依赖一起验证；正式依赖显式声明实际使用的 joblib 等包，不依赖传递导入。新库惰性导入，注册/Web 启动不加载制品或计算库。不得为迁移血压静默升级改变已有 HR/BR、血氧基线的依赖。

### 5. 输出遵循新项目契约，不新增预测后处理

成功 payload 包含 `sbp`、`dbp` 和实际质量信息，指标代码同名、类型 number、单位 `mmHg`。从两个模型各取单个预测后确认有限，不四舍五入、不限幅；完整结果和投影使用同一值。模型产生 NaN/无穷或不支持的形状时为 `RESULT.INVALID_OUTPUT`，不得只保存一项指标。非法中间特征若导致模型报错，保留执行失败分类，不将任意第三方异常归为输入或质量拒绝。

仅在结果已确认有效后，向 `InferenceInput.output_dir` 写文件，逻辑名 `processed_ppg` 对应固定文件名 `ppg-processed.csv`，`processed_scg` 对应 `scg-processed.csv`，不附加输入 UUID。列保持旧语义：PPG 为 `timestamp,ppg`；SCG 为 `timestamp,scgX,scgY,scgZ`，X/Y 为零、Z 为重建信号。通过逻辑引用返回，不包含本地路径。复用成功结果登记、任务所有权和渠道检查；失败时不登记成功指标与权威输出。

存储重组后的 `output_dir` 是 `.executions/<task_id>/<execution_token.hex>/` 隔离执行目录。算法只写收到的目录，返回后不再修改文件；不自行构造工作目录，不写 `<channel>/<任务创建日期>/outputs/<task_id>/` 正式入口，不创建或跟随发布符号链接。

两份 CSV 作为同一成功集合交给现有服务端发布机制：数据库成功事务登记不可变实际键，提交后才整组切换正式目录链接。失败、失租或事务回滚不得发布；晚到执行不能覆盖已提交集合。正式入口保持原文件名，日期采用任务创建时间转上海时区，而非执行完成日期。

下载按数据库登记的不可变实际键读取，不通过可切换正式链接解析权威文件。发布 I/O 失败不撤销成功状态；沿用下载和终态消息处理的幂等恢复，不重新推理、不增加执行次数。恢复失败但实际文件存在仍可下载，实际文件缺失按既有安全 404 处理。这些通用规则归前置变更的 `inference-runtime`、`local-file-storage` 规格所有，本变更只验证其适用于血压双文件，不重复定义或实现发布协议。

### 6. 验证基线与发布步骤

实现前记录旧源码和三个制品 SHA-256、依赖环境，建立只运行旧数值模块的隔离对照，不启动旧服务、不写回旧仓库。对同一输入和同一资料比较清洗信号、质量、PTT、PR、六维特征及 SBP/DBP。整数/分支判断必须一致，浮点对照容差明确记录并解释来源，不以放宽容差隐藏漂移。

长期测试覆盖缺失补零、无配对、IQR 清空、门槛两侧、非法结果及版本/任务隔离；不把用户健康样本或生产权重直接加入测试仓库。一次性真实样本对照作为迁移证据。工作流测试使用项目持久测试数据库并统一传 `--reuse-db`，隔离测试记录、Redis Stream 和存储目录，实际执行算法；不另建一次性数据库替代项目约定。

存储集成验收覆盖血压双 CSV 的整组发布、跨日目录归属、失租及回滚不发布，以及成功提交后发布中断的恢复。注入发布失败后验证成功状态、指标、执行次数和下载字节不变；恢复后正式链接指向同一权威执行目录，不出现新旧文件混合。注入仅作用于存储发布边界，不用 mock 替代血压计算。

## Risks / Trade-offs

- 保留补零和旧特征定义可能产生缺少有效测量支持的血压值 → 文档明确旧版兼容行为，不把结果宣称为临床有效；本次不自行修正。
- IQR 严格边界、零信号标准化等可产生 NaN → 保留计算路径，按当前执行/结果契约失败，不伪造成功。
- 两路时钟偏移直接影响 PTT → 用现有样本核查时标与重叠区间并记录，不增加隐式校准。
- VMD 残差循环没有显式模态上限 → 实测耗时并核实执行超时，不暗改算法；若真实输入暴露无法受控终止的问题，必须报告并另行确认规则变化。
- joblib 可执行对象及训练依赖未知 → 来源与哈希核验、隔离加载和受信发布；加载成功不代表安全扫描或配套关系已证明。
- 存储重组是前置依赖 → 本变更必须在其完成实现与验收后开始，核对最终接口与主规格；只使用传入 output_dir 和登记键，不自行写正式入口、不修改前置变更产物。

## Migration Plan

0. 先完成 `reorganize-file-storage-paths` 的全部实现与实际验收，确认格式声明、隔离执行目录、整组发布、幂等恢复和 POSIX 卷前提均已验证；再开始本变更。其规划状态完成本身不满足这一条件。

1. 完成旧计算与制品基线核验，在隔离环境验证两个真实模型及当前依赖的兼容性；失败即阻止发布，不使用假模型替代。
2. 实现并验证独立血压算法、固定制品资源、资料映射及失败语义；确认旧算法回归未改变。
3. 创建模型草稿，上传配套三制品，配置 sbp/dbp 指标后发布；不自动修改现有渠道选择。
4. 经授权在测试渠道选择该版本，完成实际上传、提交、消费者执行、结果查询和文件下载验证；确认输入与制品使用新布局、两份固定名 CSV 整组发布、下载读取不可变实际键，并完成发布失败恢复及失租隔离验证后，再由管理方选择目标渠道。
5. 回退通过现有渠道选择切回已发布可用版本，遵循已有草稿失效规则；保留已提交任务固定版本及其制品，不删除历史文件。首次上线无旧血压版本时，不选择新模型即可避免新增任务使用它。
