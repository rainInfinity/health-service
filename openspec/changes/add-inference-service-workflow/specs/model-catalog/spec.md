# Spec Delta

## Purpose

为管理人员配置模型种类、不可变发布版本和渠道当前版本提供明确的业务规则，使普通渠道只能使用已发布且被选定的版本，并保证版本切换不会改变已提交任务或漏掉并发产生的旧版本草稿。

## ADDED Requirements

### Requirement: 管理权限保护模型目录写入
系统 MUST 只允许有效管理渠道身份且当前具有管理权限的账号创建模型、配置版本、上传制品、定义指标、发布版本和切换渠道选择，不得接受普通渠道身份或请求中的权限字段替代管理校验。

#### Scenario: 普通用户尝试发布
- **WHEN** 普通用户或普通渠道令牌请求发布模型版本
- **THEN** 系统拒绝操作，不修改发布时间、制品或渠道选择

#### Scenario: 管理权限已撤销
- **WHEN** 曾有管理权限的账号使用未过期管理 Access 修改模型目录，但当前管理权限已撤销
- **THEN** 系统拒绝写入，已有版本与渠道配置保持不变

### Requirement: 模型和版本目录保持唯一身份
系统 MUST 支持创建模型和查询、创建其版本，拒绝重复模型代码、同模型重复版本号及不存在的所属模型；新版本在发布前 MUST 不可被普通渠道选为当前版本。

#### Scenario: 创建未发布版本
- **WHEN** 管理人员为已有模型创建合法且未重复的版本
- **THEN** 系统保存版本标识、算法标识和参数，该版本仍未发布，不在普通渠道可用模型中出现

#### Scenario: 重复或缺失目录身份
- **WHEN** 创建重复模型代码、重复版本号或引用不存在的模型
- **THEN** 系统分别返回冲突或资源不存在，不能产生重复目录或孤立版本

### Requirement: 发布依据算法契约校验完整配置
系统 MUST 在发布前校验存在可执行算法、参数有效、制品集合与声明匹配且文件存在、投影指标定义可被该版本解释；无制品算法允许零制品。仅有接口模板而没有正式执行器的算法 MUST 不可发布。

#### Scenario: 发布无制品示例版本
- **WHEN** 合法示例算法不要求权重制品，且其参数与投影指标配置有效
- **THEN** 零制品不阻止发布，版本取得发布时间并保留示例身份

#### Scenario: 发布不完整或不可执行版本
- **WHEN** 版本使用未知或未实现的算法、无效参数、缺失／额外制品、缺失物理文件或不兼容指标
- **THEN** 系统拒绝发布，版本保持未发布，不能被渠道选中

### Requirement: 已发布版本的执行配置不可变
系统 MUST 允许修改未发布版本的执行配置，并禁止原地修改已发布版本的算法标识、参数、制品及投影指标集合；再次发布同一版本 MUST 不改变其原发布时间或配置。指标语义或单位改变 MUST 使用新的指标代码。

#### Scenario: 更新未发布版本
- **WHEN** 管理人员更新尚未发布版本的算法标识、参数或投影指标集合
- **THEN** 系统保存合法更改，但仍需发布校验后才能供渠道选择

#### Scenario: 改写已发布配置
- **WHEN** 管理人员尝试替换已发布版本制品，或修改其参数、算法标识、投影指标集合
- **THEN** 系统返回冲突，历史任务仍可按原版本解释和执行

#### Scenario: 重复发布
- **WHEN** 管理人员再次发布一个已经发布的版本
- **THEN** 系统返回该已发布版本，不更新原发布时间，不生成第二套配置

### Requirement: 渠道只能选择所属模型的已发布版本
系统 MUST 为每个已知渠道和模型保留至多一个当前版本选择，选择的版本必须属于该模型且已发布；渠道选择相互独立，同版本重选不得改变任务状态。

#### Scenario: 选择不属于模型的版本
- **WHEN** 管理人员将一个模型的渠道指针指向另一模型的版本或未发布版本
- **THEN** 系统拒绝选择，现有当前指针保持不变

#### Scenario: 不同渠道独立配置
- **WHEN** 两个渠道分别选择同一模型的不同已发布版本
- **THEN** 两个选择独立生效，切换一个渠道不更改另一个渠道的配置

#### Scenario: 重选当前版本
- **WHEN** 管理人员为渠道再次选择其当前版本
- **THEN** 当前选择保持不变，不终止该渠道任何草稿

### Requirement: 版本切换原子终止旧草稿
系统 MUST 在切换渠道当前版本时原子终止该渠道原版本的所有草稿，记录 `TASK.MODEL_SWITCHED` 和完成时间；已提交或运行中的任务继续按固定版本执行，回退不得恢复已经失败的草稿。

#### Scenario: 切换时同时创建或提交
- **WHEN** 渠道切换与该渠道旧版本草稿创建或提交并发发生
- **THEN** 提交在切换前完成的任务继续执行；其余旧版本草稿全部终止，切换完成后不能再提交旧版本草稿或漏出新建旧版本草稿

#### Scenario: 回退旧版本
- **WHEN** 渠道重新选择仍保留制品的旧已发布版本
- **THEN** 新草稿可以固定该版本，已因之前切换失败的草稿不会恢复

### Requirement: 普通渠道只查询自身可用模型
系统 MUST 向已登录普通渠道用户提供分页的当前可用模型及确定版本、所需输入逻辑名和 `isExample`，只包含该渠道选择的已发布版本；不得暴露制品路径、内部参数或其他渠道配置。

#### Scenario: 查询本渠道目录
- **WHEN** 用户使用与路径匹配的普通渠道 Access 查询可用模型
- **THEN** 返回该渠道当前已发布选择和明确示例标志，未配置或未发布版本不出现

#### Scenario: 有界分页
- **WHEN** 用户以合法 offset 和不超过 100 的 limit 查询目录
- **THEN** 系统按稳定顺序返回相应分页；非法分页被拒绝，不通过无限列表暴露全部目录
