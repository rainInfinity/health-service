# Spec Delta

## MODIFIED Requirements

### Requirement: 成功结果和指标原子保存
系统 MUST 按任务固定版本校验完整输出，并在同一持久化事务保存完整结果、实际存在且选定的投影指标以及成功状态和完成时间；未产生的指标不写行。数值必须有限，布尔与数值类型不得混淆，任务失败不能留下部分成功投影。场景正常完成全部成员调用与汇总时 MUST 按成功事务保存，包括部分成员失败和全部成员失败；只有成功成员实际产生的指标允许投影。

#### Scenario: 合法结果包含部分指标
- **WHEN** 合法完整输出只产生该版本允许投影指标中的一部分
- **THEN** 完整输出保存为权威结果，只保存实际产生且类型正确的投影，其他指标不以零或 false 补齐

#### Scenario: 指标保存中断
- **WHEN** 成功写入事务在保存结果或投影时发生数据库错误
- **THEN** 整个事务回滚，不留下成功状态与结果／投影不一致的数据，不确认该消息

#### Scenario: 输出或投影无效
- **WHEN** 算法输出结构无效，或产生与选定指标不符的类型、非有限数值
- **THEN** 当前有效执行记录 RESULT.INVALID_OUTPUT，不保存成功结果或部分指标

#### Scenario: 场景全部失败仍原子保存汇总
- **WHEN** 全部成员已完成且失败，场景返回合法 ALL_FAILED 汇总并仍持有有效租约
- **THEN** 同事务保存非空完整失败汇总与 SUCCEEDED 任务终态，清空执行令牌与租约，不创建指标行，顶层失败字段为空

### Requirement: 质量拒绝原子终结为失败
当质量拒绝作为任务级错误提交时，系统 MUST 在同一事务保存原因、明细、安全摘要、失败码、完成时间和 FAILED 状态，并清空执行令牌与租约。任务级质量拒绝 MUST NOT 保存成功结果、指标投影或权威输出文件，不新增任务状态，也不将任意失败诊断放入成功结果。场景内部已捕获的成员质量拒绝属于类型化成员结果，不是任务级质量拒绝；其白名单公开信息 MUST 随合法完整汇总保存，失败成员自身仍不得产生成功指标和文件。

#### Scenario: 合法质量拒绝提交
- **WHEN** 有效执行的任务级质量拒绝事务成功提交
- **THEN** 任务为 FAILED，失败信息完整，完成时间已设置，执行令牌和租约为空，结果为空且没有成功指标或可下载的权威输出

#### Scenario: 保存质量拒绝时数据库故障
- **WHEN** 保存任务级质量拒绝的事务发生数据库错误并回滚
- **THEN** 不留下部分质量明细或失败终态，不把数据库错误再次改写为质量拒绝，也不确认仍需恢复的消息

#### Scenario: 成员质量拒绝不成为任务级拒绝
- **WHEN** PPG 场景捕获 diabetes 的合法低分拒绝并正常完成其他成员及汇总
- **THEN** 任务为 SUCCEEDED，diabetes 为 FAILED 且保留白名单质量信息，顶层 qualityFailure 和失败字段为空

## ADDED Requirements

### Requirement: 场景成员失败复用安全错误契约
场景成员失败 MUST 使用与独立算法一致的受控失败分类和安全摘要，不保存任意异常正文、堆栈、输入、资料、元数据或服务器路径。只有合法类型化质量拒绝允许非空 qualityFailure；LOW_SCORE 仅含实际有限 score 与 threshold，NO_VALID_SIGNAL 的 details 为空。伪造质量错误码、未知质量原因或损坏明细 MUST 降级为安全执行失败，普通错误的 qualityFailure MUST 为空。

#### Scenario: 输入原因使用同一公开解释
- **WHEN** 独立算法和场景成员分别报告同一个合法受控输入原因
- **THEN** 两者产生相同失败代码和安全摘要，不回显成员异常消息

#### Scenario: 伪造质量拒绝不会成为医学结论
- **WHEN** 成员仅声明质量错误码但没有合法类型化拒绝，或评分包含 NaN、布尔值及原因不匹配明细
- **THEN** 该成员按 INFERENCE.EXECUTION_ERROR 失败，qualityFailure 为 null，不阻止其他成员执行

#### Scenario: 私有内容不得进入成功的场景载荷
- **WHEN** 一个失败成员的异常消息或附加属性包含本地绝对路径、原始输入或客户端元数据
- **THEN** 场景 results 只包含安全失败字段；这些私有内容不进入持久化完整结果、详情响应或普通日志

### Requirement: 场景沿用单任务执行权和整体硬时限
场景 MUST 作为一个任务复用已有派发、版本缓存、执行令牌、租约、领取次数、硬时限、成功事务和消息确认流程，不为成员增加独立数据库任务或自动重试。任务级输入读取、存储、场景编排及最终汇总错误 MUST 按原任务失败契约处理。整体超时、失租、进程终止或事务回滚 MUST NOT 以已完成成员制造可查询部分汇总或权威文件。

#### Scenario: 部分成员完成后整体超时
- **WHEN** HR/BR 已完成，但整个 PPG 场景超过既有硬时限且仍持有有效执行权
- **THEN** 计算进程被终止，任务以 INFERENCE.EXECUTION_TIMEOUT 失败，result 为 null，不保存已完成成员指标或权威文件

#### Scenario: 全部成员完成后失租
- **WHEN** 场景已生成合法汇总，但持久化时执行令牌过期或不匹配
- **THEN** 该执行不能保存汇总或发布文件，也不能确认仍需恢复的非终态消息

#### Scenario: 已保存场景结果收到重复消息
- **WHEN** 部分成功或全部失败的场景汇总已以 SUCCEEDED 保存，随后消息重放
- **THEN** 只按现有终态规则恢复必要文件发布并确认，不重新执行成员、不增加执行次数

#### Scenario: 原始文件不可读取
- **WHEN** 任务必需原始文件在执行准备阶段不可读取
- **THEN** 任务按现有输入失败契约终结且 result 为 null，不伪造已经逐项执行的成员结果

#### Scenario: 场景汇总本身无效
- **WHEN** 成员调用已结束，但最终场景结构、指标一致性或文件归属校验失败
- **THEN** 任务以 RESULT.INVALID_OUTPUT 失败且 result 为 null，不把场景自身错误归给某个成员以绕过最终校验
