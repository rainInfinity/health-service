# Proposal

## Why

前端准备按采集方式提供“指尖 PPG 综合检测”和“指尖 PPG＋胸部 ACC 血压测量”两个入口，当前却需要按独立算法分别创建、上传和查询任务。需要增加固定组合的场景算法，在一次任务内调用既有算法并统一返回各项成功结果或安全失败信息，避免前端自行拼装算法流程。

## What Changes

- 新增 `统一PPG场景`，算法标识为 `ppg.active.offline.all.v1`，固定调用现有 HR/BR、血氧和糖尿病风险 v1。
- 新增 `统一PPG+ACC场景`，算法标识为 `ppg_acc.active.offline.all.v1`，本次仅调用现有血压 v1，不因名称中的 `all` 自动增加其他成员。
- 每个场景仍对应一个模型发布版本和一个 Task；场景版本直接绑定成员所需制品的并集，成员实现修订固定在代码中，不读取其他模型的渠道当前版本。
- 场景完整结果包含 `outcome` 与按成员分组的 `results`；每个成员公开 `algorithmKey`、`status`、`result`、`failureCode`、`failureMessage`、`qualityFailure`。
- 成员的资源加载、输入、质量、执行或结果错误只使该成员失败，其他成员继续执行。正常完成汇总时任务为 `SUCCEEDED`，测量结果通过 `ALL_SUCCEEDED`、`PARTIALLY_SUCCEEDED` 或 `ALL_FAILED` 区分；所有成员失败也保留完整失败汇总。
- 只合并成功成员的指标与文件；输出文件按成员隔离目录，并在场景 `result.output_files` 中使用成员前缀的逻辑名。失败成员的残留文件不得进入正式发布集合。
- 保留四个独立算法的计算规则、对外结果和历史任务，不自动替换现有渠道配置；文档说明新场景的发布、选择与前端读取方式。

## Capabilities

### New Capabilities

无。场景算法属于现有推理算法能力，不新增近义规格或通用工作流能力。

### Modified Capabilities

- `inference-algorithms`：增加两个固定场景的输入、制品、成员调用、分组结果和指标契约；明确阶段门禁和首个质量拒绝的终止范围是对应成员。
- `inference-runtime`：区分场景汇总成功与成员测量失败，复用安全失败映射并保留既有租约、硬超时和原子提交边界。
- `inference-tasks`：定义场景详情的两层状态及成员安全失败字段，保持顶层失败、列表摘要和单算法查询行为。
- `local-file-storage`：支持场景成员子目录及带前缀的输出逻辑名，保持失败成员不可发布、文件归属校验与受保护下载。

## Impact

- 计算包：`health_inference` 的显式算法注册、新场景实现、固定成员编排、资源初始化与结果校验；抽取现有安全失败映射为无 Django 依赖的共享能力，避免两套错误解释。
- 服务包：`infrastructure/inference_adapter.py`、`application/execution.py` 及相关文件校验，需避免成员制品失效提前击穿整个场景；普通算法继续沿用原资源检查。
- API：沿用当前模型目录、`modelId` 创建草稿、文件上传、提交、详情和下载路径；只有选择新场景模型的任务采用新结果结构，不新增任意算法列表请求或子任务 API。
- 数据：沿用 `Model`、`ModelVersion`、`Task`、`TaskMetric`、输入文件记录；预计无需数据库迁移、新配置项或依赖。场景模型名称通过现有管理流程设置，不在注册表虚构 `name` 字段。
- 文档与验证：更新 `docs/frontend-integration.md`、模型与算法开发说明、文件和任务架构说明，并覆盖真实组合执行、成员失败隔离、失败信息安全、结果一致性和文件下载。
- 不包含：前端代码、现有算法数值修正、共享预处理/评分优化、采集同步修复、医学准确性验证、并行调度、成员自动重试/独立超时、通用 DAG、生产模型发布或渠道切换。整体超时仍按当前任务失败契约处理，不保存未完成的部分汇总。
