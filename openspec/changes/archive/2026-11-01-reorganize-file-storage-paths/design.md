# Design

## Context

动机与范围见 [proposal.md](proposal.md)。当前 `LocalFileStorage.save_upload` 仅接收存储区域、流和大小限制，生成 `uploads/<UUID>.bin`；任务上传锁内已经取得算法 key，但未把创建时间传给存储层。制品上传已锁定版本，可取得模型和版本元数据。当前 HR/BR 仅声明输入 `ppg`、无制品，输出名固定为 `ppg-processed.csv`、`rsp-processed.csv`，结果校验依赖这些原名。

`run_task_inference` 和成功保存用例均验证输出属于 `task_id/execution_token` 的执行目录。数据库保存输出相对键，下载按用户、渠道、成功结果授权。现有数据库与磁盘不是原子事务，不能仅把算法 `output_dir` 改为稳定路径：失租进程仍可能继续写，导致数据库拒绝旧结果却无法阻止旧文件覆盖。

活动血氧变更正在修改版本资源工厂和算法实现；其契约声明 ONNX `spo2`、JSON `feature_names` 与 `stable_features`。本变更必须使用实施时最新接口，不覆盖其工作或重新引入静态 runner。

## Goals / Non-Goals

**Goals:** 路径可辨认归属；格式兼容；跨日一致；算法无需了解渠道、用户或业务路径；数据库已提交结果始终可指向不可变文件；正式目录简洁并可恢复发布。

**Non-Goals:** 不新增终态任务重跑 API，不自动恢复被删除的 Task，不保证仅凭输入重建资料快照和模型配置，不批量迁移已有文件，不删除孤儿或历史执行目录。

## Decisions

### 1. 服务端固定元数据决定输入路径

任务锁定查询返回创建时间、任务 ID、用户 ID、渠道和固定算法 key；存储层接收明确的不可变命名上下文，而非 ORM 或客户端路径。以任务创建时间转换到 `ZoneInfo("Asia/Shanghai")` 一次后同时生成日期与时间。新上传在锁内完成，重传总是新 UUID；日期不是上传时间，文件记录的 `uploaded_at` 仍表示真实上传完成时间。

路径为 `<channel>/<YYYYMMDD>/<YYYYMMDD_HHmmss>-<task_id>-<user_id>-<algorithm_key>-<logical_name>-<uuid.hex>.<ext>`。不依赖字符串反解析来做授权，数据库仍是在线权限依据。

所有业务字符串路径段采用一致的可逆 UTF-8 百分号编码：字母、数字、点、下划线为安全字符，其余字节编码为大写 `%HH`，其中连字符也编码，避免与输入文件的字段分隔符混淆；整段 `.`、`..` 必须编码或拒绝。固定渠道枚举保持原样，文件名中不重复渠道。编码后检查单个目录段和完整文件名的文件系统字节上限，超限安全拒绝，禁止截断或替换字符造成碰撞。原有合法常见 key `ppg.active.offline.hr_br.v1` 保持可读。

### 2. 后缀属于算法格式契约

扩充现有算法定义，增加输入和制品逻辑名到允许后缀集合的不可变映射；校验映射键与 `required_inputs`、`required_artifacts` 完全一致。迁移所有正式算法、测试注册方和文档示例，不保留旧新两套上传接口。当前 HR/BR 的 `ppg` 为 `csv`，无制品映射；已实现血氧按 `ppg: csv`、`spo2: onnx`、两份清单 `json` 声明。

应用层从实际上传对象的文件名提取最后一个后缀，转为小写并与契约匹配；无文件名、缺失后缀、不支持后缀按已有输入／制品无效错误处理。内部测试流必须显式提供来源文件名，不为无名流静默回退 `.bin`。客户端完整名称、路径、MIME 均不用于确定实际目录。CSV、JSON、ONNX 内容仍由现有算法和版本资源加载器校验；后缀不是内容真实性证明。

制品上传在版本锁内读取所属模型 code、version，生成 `<model_code>/<version>/<logical_name>-<uuid.hex>.<ext>`。目录段统一编码，仍由数据库唯一约束阻止同版本同逻辑名重传，发布后禁止更改。

### 3. 工作目录与正式目录分离，正式目录整组切换

单次执行实际文件位于任务根内 `.executions/<task_id>/<execution_token.hex>/`，算法只收到该路径，继续生成原输出名。写完后按本次令牌目录验证并禁止再修改；数据库 `result_payload.output_files` 保存这些不可变实际相对键。原始执行目录继续保留，不把文件复制到每任务正式目录，也不让旧执行持有正式目录可写目标。

对外可辨认的磁盘入口为 `<channel>/<创建日期>/outputs/<task_id>/`。实现为服务端管理的相对目录符号链接，指向同根内已成功提交的执行目录；通过同父目录的临时链接和 `os.replace` 原子替换链接，一次切换整个文件集合，保留原文件名且不增加结果 UUID。输出父目录及链接目标均严格校验根目录边界，不能直接对已有链接调用 `resolve()` 后把目标当作待替换入口。仅服务端账号可以修改存储树。

选择目录链接而非逐个覆盖 CSV：逐文件覆盖会暴露新旧混合；直接重命名覆盖已有非空目录不能在 POSIX 上保证原子性。此实现针对当前本地 POSIX 部署；部署前须验证共享卷支持符号链接和同目录原子替换，不支持时报告前提不满足，不退化为逐文件覆盖。

### 4. 数据库成功优先，发布可幂等恢复

成功保存仍在既有事务内校验令牌与租约、校验结果和指标并登记实际执行键；数据库提交成功后才执行发布。发布短事务锁定任务，重新读取已提交的成功记录，从其权威文件集合确定同一个执行目录，再替换正式链接。晚到回调必须使用重新读取的记录，不能发布回调捕获的旧 token。链接已指向正确目录时不重复替换。

事务回滚、失租或算法失败均不触碰正式链接。成功提交后、链接更新前退出可能暂时缺少正式目录：下次成功结果下载或终态消息处理调用同一发布函数恢复，不重新计算。发布 I/O 失败安全记录固定事件，不能撤销成功状态；恢复机会不依赖强制保留终态消息。数据库与文件系统依然不是原子提交，正式磁盘入口允许短暂滞后，但绝不能指向未成功提交的执行。

下载始终按数据库记录打开不可变实际键，不通过可切换链接解析权威结果，因此已打开文件不受链接替换影响。恢复发布失败但实际文件可用时仍可下载；实际文件缺失沿用安全 404。不新增数据库字段：已有输出键表达成功执行目录，只有目录一致且令牌合法的新记录才参与新式发布，旧记录直接按原键读取。

“最新一次成功覆盖”定义为正式入口指向运行时合法接受的最新成功集合，不改变现有终态不可重提语义。现有恢复重试只有一个可提交成功者；本变更不创造人工重跑机制。整组切换边界可由存储层测试验证，不在产品中增加重置任务的入口。

### 5. 存量读取不依赖新名称解析

输入和制品读取继续使用已登记 storage_key 加根目录检查，不强制新模板，不推断旧 `.bin` 文件类型。旧 `outputs/<task_id>/<token>/` 结果保持可读；不为了生成新式正式链接扫描存量或搬迁文件。新增执行仅写新工作目录和新正式入口，删除旧写入命名分支但保留通用登记键读取能力，这不是双写或新旧算法兼容层。

## Risks / Trade-offs

- 文件路径包含用户 ID → 仅供受控磁盘运维使用，不作为公开静态目录，不写入公开错误或常规日志，不替代权限检查。
- 格式后缀校验会拒绝以前接受的无名／错误后缀上传 → 同步接口文档、直接调用和测试；旧已登记文件不受影响。
- 很长的算法 key、逻辑名或版本编码后超出文件系统限制 → 写盘前按 UTF-8 字节长度校验，返回安全错误而非截断。
- 数据库已提交但链接发布失败 → 保持成功记录与不可变字节，幂等恢复链接，不承诺文件系统与数据库原子提交。
- 隔离目录保留增加占用 → 明确沿用不自动清理策略，本次不扩张为 GC。
- 路径包含 task_id 仍不足以完整复现模型执行 → 不把模型制品、参数和资料快照恢复能力当作本次验收目标。
- 活动 SpO2 变更同改接口 → 实施前核对其完成状态和最新工厂，迁移当时全部已注册算法与调用方；不重写该变更工件或计算逻辑。

## Migration Plan

1. 停止新上传和执行领取，排空消费者，备份数据库和两类存储根；实施阶段若需操作真实环境必须另获授权。
2. 一次切换全部算法格式声明、上传命名、执行工作目录和发布读取调用，根目录配置保持不变，无新增环境变量或 schema 迁移。
3. 在隔离存储与项目持久测试数据库证明真实上传、重传、消费者执行、发布、下载、旧键读取，以及注入发布中断后的恢复；采用 `--reuse-db`。
4. 恢复服务前确认卷支持符号链接与原子替换，更新运行与开发文档，不移动旧文件。
5. 回退须再次排空消费者，回到能按通用登记键读取新旧结果的已验证版本；不能假定旧版的执行目录校验理解 `.executions`。保留现有数据和发布链接，必要时修复前滚，不通过删除新数据完成回退。
