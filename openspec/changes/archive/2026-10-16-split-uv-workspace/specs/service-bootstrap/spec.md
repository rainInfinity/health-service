# Spec Delta

## ADDED Requirements

### Requirement: 可选择安装的双成员工作区
项目 MUST 提供 `health-service` 与 `health-inference` 两个可安装的工作区成员，分别声明各自直接运行依赖；业务成员 MUST 显式依赖工作区内的计算成员，计算成员 MUST NOT 依赖业务成员。两者 MUST 由仓库根目录的单一锁文件统一解析，默认共享工作区虚拟环境；公共开发工具 MUST 与成员运行依赖分开声明。

#### Scenario: 从根目录安装整个工作区
- **WHEN** 从干净检出的仓库按锁文件安装全部成员及公共开发依赖
- **THEN** 两个成员和验证工具均可用，无需为子目录生成额外锁文件或单独解析版本

#### Scenario: 选择业务成员自动取得计算依赖
- **WHEN** 在干净环境中按锁文件安装业务成员及其运行依赖
- **THEN** 本地工作区中的计算成员同时可用，不需要从外部包索引获取同名业务或计算项目

### Requirement: 计算成员可独立安装运行
系统 MUST 支持仅安装计算成员及其运行依赖，在没有业务成员、Django、数据库配置或 Web 请求的环境中执行内置示例；导入与执行 MUST 不依赖仓库源码路径注入。

#### Scenario: 仅安装计算成员执行合成样本
- **WHEN** 在干净的 Python 3.13 环境中按锁文件仅安装计算成员、不安装公共开发依赖，从仓库之外的工作目录向示例传入附带合成 PPG 文件的有效路径
- **THEN** 无需安装 Django 或配置数据库即可得到 `example: true`、10 个样本、0.9 秒和 10 Hz 的诊断结果，不导入业务成员

### Requirement: 工作区相对目录配置保持仓库语义
服务 MUST 将日志、任务数据和模型制品目录的相对配置值相对于仓库根目录解析；迁移为工作区成员后，默认目录 MUST 继续为仓库下的 `logs`、`var/tasks` 和 `var/model-artifacts`，不得因入口或工作目录变化而改用成员目录或其他工作目录。

#### Scenario: 默认目录在成员迁移后保持不变
- **WHEN** 已安装业务成员，从仓库根目录以外启动配置且未覆盖上述目录
- **THEN** 服务仍使用仓库根目录下的默认日志和数据目录

#### Scenario: 显式相对目录不跟随工作目录
- **WHEN** 为日志、任务数据或模型制品设置有效的相对目录，并分别从仓库根目录与其他工作目录加载配置
- **THEN** 两次加载解析到相同的仓库级目录，不要求移动已有文件

## MODIFIED Requirements

### Requirement: 可复现的 Web 运行环境
系统 MUST 在 Python 3.13 环境中使用提交到仓库的单一 `uv.lock` 安装 Web 服务及验证所需依赖，通过已安装的业务工作区成员启动 Web 和管理命令，不依赖源码目录注入；启动 Web MUST 不要求安装或加载可选的推理运行时依赖。

#### Scenario: 仅安装 Web 依赖
- **WHEN** 在干净的 Python 3.13 环境中按锁文件安装 Web 依赖，且未安装推理运行时依赖
- **THEN** Django ASGI 应用可以加载并由 ASGI 服务器启动

#### Scenario: 干净检出可复现依赖
- **WHEN** 从干净检出的仓库按已声明的锁文件运行安装命令
- **THEN** 安装过程无需重新解析依赖即可使用仓库中的锁定版本

#### Scenario: 不注入源码目录即可启动
- **WHEN** 已按锁文件安装业务成员及其运行依赖，提供完整有效配置，未设置源码 `PYTHONPATH` 或 ASGI 源码目录参数
- **THEN** 管理配置检查能够完成，ASGI 服务能够启动并通过 HTTP 提供 API 文档或 OpenAPI 响应

### Requirement: 可选环境文件与配置优先级
服务 MUST 在加载 Django 配置时读取仓库根目录中存在的 `.env`，不得将工作区成员目录当作配置根；此行为 MUST 与启动时的工作目录及管理命令、ASGI 入口无关。已有的进程环境变量 MUST 优先于文件中的同名值。没有 `.env` 时仍 MUST 支持仅凭完整的进程环境变量启动，不得因此放宽必填配置要求。

#### Scenario: 通过环境文件启动
- **WHEN** 仓库根目录的 `.env` 提供必需的密钥、允许的主机和 PostgreSQL 连接信息，进程未设置这些变量
- **THEN** 管理命令和 ASGI 入口均使用文件中的配置加载服务，并仍以 PostgreSQL 为数据库

#### Scenario: 进程环境变量覆盖文件
- **WHEN** 进程环境变量和 `.env` 对同一配置项给出不同值
- **THEN** 管理命令和 ASGI 入口均使用进程环境变量的值

#### Scenario: 环境文件缺失
- **WHEN** 仓库根目录没有 `.env`，但进程提供所有必需配置
- **THEN** 服务仍可以加载；若必需配置缺失，则明确报告配置错误

#### Scenario: 从其他工作目录启动
- **WHEN** 进程从仓库根目录之外启动 Django 且仓库根目录存在 `.env`
- **THEN** 服务读取仓库根目录的 `.env`，而不误读当前工作目录中的同名文件

#### Scenario: 成员目录存在同名环境文件
- **WHEN** 仓库根目录和业务成员目录的 `.env` 对配置项给出不同值，进程没有覆盖该项
- **THEN** 服务使用仓库根目录的值，不将成员目录的文件作为补充或替代配置
