# Proposal

## Why

首页和历史页仍使用固定健康读数，现有任务接口虽然能够返回算法报告，却不能按指标直接查询最近有效结果和日期区间记录。需要在既有任务之上提供统一健康记录，支持真实数据展示，同时保留独立算法与场景成员的权威结果合同。

## What Changes

- 新增当前账号、当前渠道的 `GET /api/v1/{channel}/measurements/latest` 与 `GET /api/v1/{channel}/measurements`，覆盖血压、心率、呼吸率、血氧和糖尿病风险五类记录。
- 明确产品“检测时间”为服务端最终接受提交时冻结的 `submittedAt`，用于最新结果选择、历史日期筛选和稳定排序；不采用 `finishedAt`，不新增 `capturedAt`，不要求原生采集端提供日历时间。
- 最终提交增加可选 `measurement`，仅包含 `captureMethod`、`captureMode`、`durationMs`；独立于私有 `clientMetadata` 原子冻结，任务详情公开该类型化对象。兼容无请求体的旧提交，旧数据缺失属性保持未知。
- 健康记录从现有权威结果映射，兼容四个独立算法和两个统一场景；仅纳入实际成功的对应结果，正确排除任务失败、成员失败、全部成员失败和示例结果，血压保持同任务成对。
- 允许有有效 `submittedAt` 的既有任务参与健康查询，不因缺少新增采集属性或未选择可选 TaskMetric 投影而静默漏掉有效结果；不回填或重跑历史算法。
- 历史接口沿用 offset 分页和北京时间日历日期，不引入固定快照、游标、变化推送或聚合接口。文档明确前端完整区间加载后计算统计，已知数据变化时整段刷新，不承诺跨页并发快照一致性。

## Capabilities

### New Capabilities

- `health-measurements`：统一健康记录的身份、结果来源、检测时间、最新有效结果、日期分页查询及安全隔离合同。

### Modified Capabilities

- `inference-tasks`：最终提交可冻结可选类型化采集属性，并在本人任务详情中公开；不改变现有任务摘要、私有元数据和结果合同。
- `health-data-model`：任务持久化可空采集方式、主动来源和实际时长，保持旧记录与提交事务的一致性，支持按提交时间查询。

## Impact

- 服务包：扩展任务请求、内部数据、详情响应、提交用例及持久化；新增按健康记录职责分离的请求／响应、用例、ORM 查询和 API 路由。
- 数据：新增任务采集属性列、完整性约束及账号／渠道／提交时间排序索引；保留 Task、TaskMetric 和权威 result，不新增健康结果真值表，不改变版本可选投影语义。
- 合同：更新自动生成的 OpenAPI 声明、`docs/frontend-integration.md`、`docs/development/inference-tasks.md` 及必要架构说明。所有响应时间沿用现有北京时间格式，不修改 `api-response` 时间规格。
- 验证：覆盖旧提交兼容、冻结与回滚、独立／场景映射、缺投影历史、部分成功、血压成对、乱序完成下的最新结果、日期边界、分页及账号／渠道隔离。
- 外部依赖：前端与 SDK 后续需要接入 DTO、任务串联、完整区间加载与刷新；目标渠道模型、制品和消费者可用性需在联调环境确认，本变更不声称已部署。
- 不包含：前端或 SDK 代码、原生采集修改、模型发布或渠道切换、面部／被动结果上传、医学评估规则、风险趋势、历史聚合、固定快照、离线队列、任务取消／删除及管理端扩展。
