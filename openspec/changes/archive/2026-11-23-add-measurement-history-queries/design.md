# Design

## Context

动机和范围见 `proposal.md`。当前 `submit_user_task` 在现有锁顺序内冻结资料、元数据和 `submitted_at`，`mark_task_submitted` 原子更新，数据库提交后派发。任务详情读取权威 `result_payload`；任务列表只加载摘要，现有两条路径不能直接承担按指标的健康查询。

`application/execution.py` 在保存成功前调用固定算法结果校验器，再将权威结果和版本选中的 TaskMetric 同事务保存。版本允许只选择部分指标；因此 TaskMetric 是可选派生投影，不是所有有效读数的完整索引。直接以投影存在性作为查询准入，会漏掉已有成功结果。

四个独立算法和两个统一场景已经实现。`add-unified-offline-scenes` 的任务完成但尚未归档，场景两层状态应同时参考其已存在 delta 和实际实现，不重复实现成员执行、失败隔离或结果保存。

所有新合同沿用现有认证、JSON 封套、`BeijingDateTime` 和 PostgreSQL。用户已确认产品检测时间为服务端接受 submit 的时间，首版不要求跨分页固定快照。

## Goals / Non-Goals

**Goals:**
- 将已有提交和结果不变量复用于健康查询，保持结果唯一来源。
- 在分页前完成可公开有效读数筛选，保证静态数据集下计数、页长和 latest 一致。
- 覆盖没有新增属性或没有可选投影的合法历史结果，避免历史回填和算法重算。

**Non-Goals:**
- 不重构算法执行、投影发布、文件存储或消息恢复机制。
- 不以采集自报属性验证传感器位置、模型输入适配性或医学有效性。
- 不为并发分页维持数据库事务、快照令牌或变更订阅，不在后端提供统计或评估。

## Decisions

### 1. 复用 submittedAt，不新增第二个检测时间

新健康记录直接返回 `submittedAt`，不新增 `measuredAt` 或 `capturedAt` 别名。其值来自原提交事务，内部保留数据库时间精度，响应复用北京时间秒级格式；排序使用内部精度，时间相同时按任务 ID 倒序。

这是产品归档时间，不是原生正式窗口起点；上传或提交延迟会改变归档日期。后端文档必须写明该语义，并明确取代前端建议文档中按实际采集时间归档的建议。已有任务没有提交时间则排除，不回退到完成或创建时间。

备选：实际采集时刻需要原生墙钟锚定，已不采用；推理完成时刻受排队和计算影响，也不采用。复用原字段还避免修改全局时间规格和原生采集桥接。

### 2. 三个任务列保存可选、完整的采集属性

在 Task 增加可空 `capture_method`、`capture_mode`、`duration_ms`，时长采用有符号 64 位整数存储，请求限制为该存储范围内的严格正整数，拒绝布尔、字符串和小数。枚举在本轮只允许两种指尖方式和主动来源。

请求 `measurement` 可省略或为 null；非空必须是含三项的完整对象，额外字段拒绝。与 `clientMetadata` 并列，但不复用私有 JSON，也不混入健康资料。沿现有 `submit_and_dispatch_user_task → submit_user_task → mark_task_submitted` 透传和冻结，不改变锁顺序、状态冲突或提交后派发边界。

数据库约束表达为“三项显式全空，或三项显式非空且枚举／时长合法”；草稿必须全空，避免 SQL NULL 三值逻辑让不完整属性绕过约束。新增采集属性只在详情查询字段集中加载，通过内部类型和白名单响应返回 `measurement`；旧任务和草稿返回 null，任务摘要保持不变。

备选：仅存 JSON 省去列定义但弱化约束，不采用；将自报方式从输入文件或算法推导会制造事实，不采用。也不新增未确认的采集方式与算法绑定规则。

### 3. 从权威结果构建记录，不把 TaskMetric 当准入门槛

采用固定算法到公开指标的显式映射。独立算法取顶层载荷，场景取 `results.<member>.result`，并检查成员状态和实际 `algorithmKey` 与固定场景一致：

| metric | 独立算法／成员后缀 | 结果读数键 | 对外 code 与单位 |
| --- | --- | --- | --- |
| bloodPressure | ppg_acc.active.offline.bp.v1 / bp | sbp、dbp | sbp、dbp / mmHg |
| heartRate | ppg.active.offline.hr_br.v1 / hr_br | hr | hr / beats_per_minute |
| respirationRate | ppg.active.offline.hr_br.v1 / hr_br | br | br / breaths_per_minute |
| oxygenSaturation | ppg.active.offline.spo2.v1 / spo2 | spo2 | spo2 / percent |
| diabetesRisk | ppg.active.offline.diabetes.v1 / diabetes | prob | diabetes_probability / ratio |

两个已支持场景分别为 `ppg.active.offline.all.v1` 和 `ppg_acc.active.offline.all.v1`。版本来源始终是任务固定版本，场景的实际算法来源使用成员键，不关联当前渠道版本选择。

`recordId` 固定为 `<taskId>:<metric>`。quality 只提取对应结果中合法的实际 score/threshold，缺少或不合法则 null，不带出其他 JSON。riskLevel 在风险记录取合法 `risk_level`，其余为 null；风险结果缺少必要概率或合法档位则不生成该类记录。读数保留原值，不重新使用模型评估规则。

备选：TaskMetric 加载简单但不完整；补写所有历史投影会改变版本选中集合的语义；另建健康结果表引入双写和迁移。这三者均不采用。本轮不读取 TaskMetric 来回填已存在于权威结果的读数，也不改它的写入路径。

### 4. 共享固定映射，数据库先筛选，再计数和分页

新增按职责组织的 measurement 模块：领域层描述固定结果路径、成员与单位；持久化层构建过滤及标量选取；应用层验证日期／分页并组装记录；请求／内部／响应类型和 API 路由分别沿现有目录组织。固定映射同时驱动过滤和读数提取，避免两套条件漂移；不引入通用动态结果解释器。

查询基础集限定账号、来源渠道、成功状态、非空 submitted_at 和已支持的非示例算法；不支持或已移除算法只排除，不调用会使整次查询失败的未知注册项。场景进一步限定成员成功、身份匹配和所需结果路径。使用 PostgreSQL JSON 类型判断，拒绝读数字符串、布尔、null 和错误结构；必要转换用类型保护后的 CASE，不能直接对任意历史 JSON 强制转数值。

生产结果已在写入前通过原算法校验，这是查询依赖的不变量。读取时针对公开记录必要字段做防御性合法性检查，不重跑算法，也不检查原波形文件是否仍存在来决定读数有效性。quality 的缺失不影响有效读数。所需读数和风险档位等准入条件必须进入数据库谓词，不能先取页再在 Python 丢弃不合格任务。

一个 metric 请求以 Task 为记录单位，血压同一 JSON 载荷同时要求两项；不 join 多条 TaskMetric，避免重复 count。仅从命中页选取公开读数、质量、风险、来源和版本等必要标量，不加载完整波形数组或对每条再查详情。

为 Task 新增 `(user, channel, -submitted_at, -id)` 的复合索引，保留既有服务其他查询的索引。先以账号、渠道和时间收窄，再做固定 JSON 谓词；不预先为每个算法路径增加 GIN 索引或持久化视图。

### 5. latest 与历史复用同一有效记录条件

latest 对五种指标分别执行有界的首条查询；固定五次查询比复杂的跨 JSON 分组查询更易维护，不扫描最近任务后猜测各指标。无数据仍返回五个键和 null，失败和处理中任务不覆盖旧有效值。

历史严格解析 `metric`、日期与分页；北京时间包含首尾的日期转为提交时间半开区间，不能使用服务器默认时区。查询使用同一个过滤定义完成 total 与 offset/limit，再以 submitted_at、任务 ID 倒序返回。默认 offset=0、limit=20，最大 limit=100；不新增日期区间天数限制、模型过滤参数或记录详情端点。

计数与取页都读取当前数据，不承诺两条 SQL 或多次 HTTP 请求之间固定集合。静态数据集的 total 必须正确；并发变化后 total 与后续页可能变化，不为它提高事务隔离级别。

### 6. 明确简单分页的消费边界，不在本仓库实现前端刷新

对接文档写明：已知测量结束产生新有效结果、发现 total 变化或重复 recordId 时，前端丢弃该轮已取页面并重取整个区间。切换账号、渠道、指标或日期范围后不能混入旧请求结果；这里只定义消费合同，不修改 SDK／前端代码。

列表可先显示，完整区间加载成功前不展示最终统计；任一页失败不能当作空页结束。接口无法发现所有跨页变化，刷新方案只提供已确认的首版一致性水平，不把去重描述为完整性保证。

记录包含版本和来源供客户端保守分组；未确认可比性时，按采集方式、来源、实际成员算法和固定 versionId 区分，缺失来源保持未知，不与明确来源自动合并。接口本身不计算均值，也不建立跨版本医学可比性目录。风险档位不求均值，不因返回概率自动开放风险趋势。

## Risks / Trade-offs

- [提交时间晚于真实采集] → 文档明确为产品归档时间，保留 actual durationMs 的独立含义，不宣称原生发生时刻。
- [JSON 谓词成本高于扁平投影] → 先用账号／渠道／提交时间索引过滤，只选页内标量；不以漏历史数据换取更简单的查询，后续按实际查询证据再优化。
- [历史载荷结构异常] → 类型保护和固定路径排除无效读数，质量白名单可为空，未知算法不使整个查询失败；不在 Python 过滤页内记录。
- [跨页变化无法全部检测] → 明确无快照保证、完整区间加载状态与整段刷新，不声称统计严格实时一致。
- [同名指标跨来源或版本不可比] → 返回真实身份字段，文档要求保守分组；参考区间、风险中文解释及跨版本可比性不是后端自动推断。
- [部署完成但推理不可用] → 发布前单独确认目标渠道模型、制品、消费者与依赖，并走真实任务联调；OpenAPI 存在或本地合同测试通过不代表模型已部署。

## Migration Plan

1. 增量迁移添加三项 nullable 列、完整性约束和复合索引，无业务数据回填；升级前后既有结果及可选投影保持不变。
2. 部署支持新提交字段及查询的服务；原消费者不需要理解采集属性，执行持久化只更新既有执行字段，不会覆盖新增列。
3. 执行定向数据库和 API 验证，再更新后端正式对接说明供 SDK／前端后续接入；检查目标环境模型和消费者是发布验证，不是迁移中的自动配置动作。
4. 应用回滚保留增量列和已保存属性，旧代码可忽略它们；不要直接反向迁移删除已采集属性。若确需物理回滚，先导出受影响属性并单独确认数据删除，不能作为自动回滚步骤。
