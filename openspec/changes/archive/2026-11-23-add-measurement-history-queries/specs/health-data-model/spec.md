# Spec Delta

## ADDED Requirements

### Requirement: 任务持久化可空且成组的采集属性
系统 MUST 为任务保留可空的采集方式、采集来源、实际采集时长；三项 MUST 全部为空或全部为合法值。当前合法方式为 `fingertip`、`fingertip_chest`，合法来源为 `active`，时长为正整数毫秒。未提供属性 MUST 保持未知，不填默认值；草稿 MUST 不保存冻结采集属性，不新增独立采集时间列。

#### Scenario: 新建草稿和旧任务迁移
- **WHEN** 创建草稿或为已有任务应用采集属性迁移
- **THEN** 三项初始均为空，原状态、归属、快照、提交时间、完整结果、指标和文件关系不被修改

#### Scenario: 保存完整采集属性
- **WHEN** 任务成功提交并提供合法采集方式、主动来源和实际时长
- **THEN** 三项与提交状态一同持久化，后续执行和结果保存保留该组值

#### Scenario: 不完整或非法数据库值
- **WHEN** 持久化仅填写部分采集属性、非法枚举、非正时长，或在草稿保存非空采集属性
- **THEN** 数据库拒绝不完整或不合法记录，不允许写入只知方式却缺来源和时长的冻结对象

### Requirement: 检测查询扩展保持既有结果和投影语义
采集属性和按提交时间查询的扩展 MUST 保留既有任务权威结果、执行状态约束、审计及可选指标投影语义，不新增与任务竞争的健康结果真值。无新增采集属性或未选择某些投影的历史任务 MUST 不被迁移删除、补造或自动重算；查询不得因派生记录需求修改已发布版本及历史投影。

#### Scenario: 历史成功任务升级
- **WHEN** 对有完整结果但只保存部分或没有指标投影的成功任务执行迁移
- **THEN** 原结果、原投影集合和提交时间保持不变，新增属性为空；是否进入健康查询由统一记录合同判断

#### Scenario: 任务在后台进入终态
- **WHEN** 后台将已提交任务更新为运行、成功或失败
- **THEN** 仍遵守原租约、结果与失败字段约束并维护审计信息，不改写冻结采集属性或以结束时间替换提交时间
