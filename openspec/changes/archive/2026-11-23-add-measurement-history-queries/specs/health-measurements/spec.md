# Spec Delta

## Purpose

为当前账号和来源渠道提供由既有推理结果派生的统一健康记录，使首页和历史页能按一致的检测时间、指标身份和有效性规则读取真实读数，同时保留原算法报告、模型版本和质量信息的准确含义。

## ADDED Requirements

### Requirement: 健康记录具有稳定身份和明确来源
系统 MUST 按一个任务的一类指标生成一条统一健康记录，支持 `bloodPressure`、`heartRate`、`respirationRate`、`oxygenSaturation`、`diabetesRisk`。记录 MUST 返回稳定的 `recordId`、`taskId`、`metric`、`submittedAt`、`captureMethod`、`captureMode`、`durationMs`、`readings`、`quality`、`riskLevel`、`modelId`、`versionId`、`version`、`algorithmKey`；同一任务不同指标不得共用记录身份。

#### Scenario: 同一场景产生多类记录
- **WHEN** 一个统一 PPG 任务的 HR/BR、血氧和风险成员均成功
- **THEN** 产生四条记录，`recordId` 分别为 `<taskId>:heartRate`、`<taskId>:respirationRate`、`<taskId>:oxygenSaturation`、`<taskId>:diabetesRisk`，共享任务 ID，各指标身份保持稳定

#### Scenario: 场景版本与成员算法不混淆
- **WHEN** 返回统一场景任务产生的某项记录
- **THEN** `modelId`、`versionId`、`version` 来自任务固定的场景版本，`algorithmKey` 来自实际成功成员，不把场景版本描述为成员独立模型的发布版本

### Requirement: 产品检测时间固定使用提交时间
健康记录 MUST 使用服务端最终接受任务提交时冻结的 `submittedAt` 作为产品检测时间，最新选择、日期筛选和排序 MUST 使用该时间；不得使用完成时间、创建时间或客户端元数据替代，不新增 `capturedAt`。缺少 `submittedAt` 的任务 MUST 不进入健康查询。响应时间 MUST 沿用既有 `Asia/Shanghai`、`YYYY-MM-DD HH:mm:ss` 合同。

#### Scenario: 采集上传与推理跨日
- **WHEN** 一个任务在某日提交而在次日推理成功
- **THEN** 健康记录归入提交日，返回原提交时间，不归入完成日，也不把该时间宣称为原生采集窗口开始时刻

#### Scenario: 旧记录有提交时间
- **WHEN** 旧成功任务存在合法提交时间但没有新增采集属性
- **THEN** 任务可按其他有效性规则产生记录，采集方式、来源和时长均返回 `null`，不从输入文件或算法名称推断这些属性

### Requirement: 统一读数沿用对应算法原值和单位
`readings` MUST 按 `code` 明确读数，数值保持权威结果原值；单位沿用算法合同，不在查询中翻译、舍入、限幅或重算。血压 MUST 同任务成对返回 `sbp`、`dbp`。质量 MUST 为对应实际成功结果的 `score/threshold` 白名单或 `null`，不得制造默认分数；非风险记录的 `riskLevel` MUST 为 `null`。

#### Scenario: 返回五类指标的读数
- **WHEN** 对应正式算法成功并具有合法结果
- **THEN** 血压返回 `sbp/dbp` 和 `mmHg`，心率返回 `hr` 和 `beats_per_minute`，呼吸率返回 `br` 和 `breaths_per_minute`，血氧返回 `spo2` 和 `percent`，风险从原结果 `prob` 返回 `diabetes_probability` 和 `ratio`

#### Scenario: 心率和呼吸率共享实际质量
- **WHEN** 同一个 `hr_br` 成员产生心率与呼吸率记录
- **THEN** 两条记录使用该成员同一次实际质量；合法质量缺失时返回 `null`，不补默认分数或阈值

#### Scenario: 保留风险编码而不重新分级
- **WHEN** 返回有效糖尿病风险结果
- **THEN** `riskLevel` 保存原 `risk_level` 的整数编码，保留原 `prob` 数值，不重新计算风险档位，不返回血糖值或临床患病概率解释

#### Scenario: 血压缺少一项
- **WHEN** 某任务结果没有同次有效的收缩压或舒张压
- **THEN** 不生成该任务的血压记录，不与其他任务的读数组合

### Requirement: 健康记录只来自已支持的真实有效结果
系统 MUST 显式识别现有四个正式独立算法及两个统一场景的结果合同，仅为任务成功且对应结果成功有效的指标产生记录。场景 MUST 校验对应成员身份和状态，不仅检查任务顶层状态。失败、处理中、质量拒绝、示例及不支持的算法结果 MUST 不产生健康记录；不得重跑算法或改写原 `result`。

#### Scenario: 独立算法成功
- **WHEN** HR/BR、血氧、血压或糖尿病风险的正式独立任务成功且对应载荷有效
- **THEN** 从其权威结果生成对应记录，不要求结果具有场景包装结构

#### Scenario: 场景部分成功
- **WHEN** 统一 PPG 场景的 HR/BR 成员成功，血氧和风险成员失败
- **THEN** 仅产生心率、呼吸率记录，不为失败成员生成零值或默认读数

#### Scenario: 所有成员失败但任务汇总成功
- **WHEN** 任务为 `SUCCEEDED`，场景汇总为 `ALL_FAILED`
- **THEN** 不产生任何健康记录，既有任务详情仍可读取完整成员失败汇总

#### Scenario: 顶层失败或未结束
- **WHEN** 任务尚未成功，或因质量、技术错误、整体超时而失败
- **THEN** 不产生健康记录，不能将中途已计算成员或输出文件存在性作为成功依据

#### Scenario: 示例或不支持的历史算法
- **WHEN** 数据中存在示例执行器或当前未支持算法的成功任务
- **THEN** 健康查询排除该任务，不将模型名称或伪造载荷当作受支持算法的依据，也不影响其他合法记录的查询

### Requirement: 可选指标投影不决定健康记录是否存在
系统 MUST 以固定算法合同下的权威结果判断读数，不得因版本未选某个可选指标投影而丢失有效健康记录。任务结果和现有指标投影的保存合同 MUST 保持不变，不为健康查询重写已发布版本配置、补写未选指标或要求用户重新检测。

#### Scenario: 旧版本只投影心率
- **WHEN** 一个有提交时间的历史任务成功产出心率和呼吸率，但版本仅选择心率投影
- **THEN** 健康查询仍能返回心率和呼吸率记录，原指标表不被查询操作补写

#### Scenario: 血压没有可选投影但权威结果完整
- **WHEN** 成功血压任务有同次合法 `sbp/dbp`，但未选择这两个指标投影
- **THEN** 仍产生一条成对血压记录，不因缺少投影行返回无记录

### Requirement: 首页分别读取每项最近有效结果
`GET /api/v1/{channel}/measurements/latest` MUST 返回固定的五个指标键，每项为统一记录或 `null`。系统 MUST 对各指标独立按 `submittedAt`、任务 ID 的稳定倒序选择最新有效记录，不得只读取最新一条任务，也不得依赖当前渠道版本指针解释历史结果。

#### Scenario: 新提交尚未成功
- **WHEN** 用户最新提交的任务处理中、失败，或对应成员失败，但此前存在有效记录
- **THEN** 该指标仍返回此前最新有效记录，其他指标按各自结果独立选择

#### Scenario: 推理完成顺序与提交顺序相反
- **WHEN** 较早提交的任务晚于较新提交的任务完成，两个任务结果均有效
- **THEN** 返回较新提交任务的记录；提交时刻相同时用较大任务 ID 确定最近

#### Scenario: 全部没有记录
- **WHEN** 当前账号和渠道没有任何有效健康记录
- **THEN** HTTP 200 的 `data` 仍包含五个固定指标键，值全部为 `null`

#### Scenario: 渠道切换模型版本
- **WHEN** 渠道当前版本已切换，但最近有效记录属于旧的任务固定版本
- **THEN** 仍可返回该记录，并保留旧任务版本及其实际算法来源

### Requirement: 历史按指标和北京时间日期分页
`GET /api/v1/{channel}/measurements` MUST 接受必填 `metric/from/to`，日期为包含首尾的北京时间 `YYYY-MM-DD`；`offset` 默认为 0 且为非负整数，`limit` 默认为 20 且为 1–100。响应 MUST 含 `items/total/offset/limit`，按提交时间和任务 ID 稳定倒序；每条直接包含读数，`total` 为整个筛选条件的有效记录数，不是当前页长度。

#### Scenario: 北京时间日期边界
- **WHEN** 请求某一日期至另一日期的记录
- **THEN** 纳入起始日零点及结束日最后时刻的提交，不纳入结束日次日零点提交，不使用服务器默认或客户端时区解释日期

#### Scenario: 失败夹杂和血压双读数
- **WHEN** 多个任务中夹杂失败结果，或每条有效血压包含两项读数
- **THEN** 先确定有效记录再计数与分页，每个任务的血压只计一条，不出现先分页再剔除造成的错误总数或页内缺口

#### Scenario: 无记录或偏移越界
- **WHEN** 筛选范围无有效记录，或偏移已超过该范围末尾
- **THEN** 返回空 `items` 和正确筛选总数，保留请求的分页参数，不将空页视为请求失败

#### Scenario: 非法查询输入
- **WHEN** 指标不支持、日期格式非法、起始日期晚于结束日期，或分页参数越界
- **THEN** 返回既有 HTTP 422 和 `INVALID_INPUT` 合同，不静默纠正参数

### Requirement: 简单分页明确不提供跨请求固定快照
历史查询 MUST 使用普通 offset 分页，不返回固定快照标识、游标、统计值或趋势点，不承诺跨页并发一致性。对接合同 MUST 明确前端取得完整筛选区间后才能展示最终统计；已知测量完成、总数变化或重复记录等已检测变化发生时整段刷新，不能只刷新第一页或混用旧页。

#### Scenario: 分页期间有新结果
- **WHEN** 两次分页请求之间有新有效结果进入筛选区间
- **THEN** 后续请求允许返回更新后的集合及总数；客户端合同要求发现变化后丢弃该轮分页并整段重取，不宣称接口已冻结原集合或能自动发现所有变化

#### Scenario: 完整区间尚未取得
- **WHEN** 客户端只加载部分页面或某一页请求失败
- **THEN** 对接合同允许先展示已有列表，但不把部分均值、极值和趋势标为完整区间最终结果

#### Scenario: 不同算法版本或风险指标
- **WHEN** 区间包含未经确认可比较的来源、算法版本，或糖尿病风险记录
- **THEN** 记录保留来源和版本供客户端保守分组，不宣称同名指标自动可合并；不因概率可返回而自动开放风险趋势或风险档位均值

### Requirement: 健康查询保持认证隔离和安全公开边界
两个健康查询 MUST 复用既有 Bearer 认证、普通渠道约束、JSON 封套和请求标识，并始终同时限定当前账号与来源渠道。公开记录 MUST 只包含声明字段，不包含完整资料快照、私有元数据、内部诊断、原始输入或本地路径；报告和波形继续由关联任务接口获取，不新增记录详情接口。

#### Scenario: 账号和来源渠道隔离
- **WHEN** 当前用户查询最新或历史健康记录
- **THEN** 只返回该账号在令牌匹配渠道的记录，其他账号及同账号其他渠道的数据均不进入记录和总数

#### Scenario: 无认证或令牌渠道不匹配
- **WHEN** 请求缺少有效认证，或令牌渠道与路径不同
- **THEN** 分别沿用既有 HTTP 401、403 及结构化错误，不泄露健康记录

#### Scenario: 查询返回安全白名单
- **WHEN** 权威结果或私有任务字段中包含路径、原始数据和额外内部信息
- **THEN** 健康记录仅返回声明的读数、质量与来源字段，完整报告和文件仍按本人任务授权读取
