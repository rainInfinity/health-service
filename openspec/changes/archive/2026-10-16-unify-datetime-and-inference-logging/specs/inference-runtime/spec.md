# Spec Delta

## ADDED Requirements

### Requirement: 消费者生命周期可从日志辨认
独立消费者 MUST 在启动时输出启动事件，在消费依赖初始化及首轮数据库扫描成功后输出就绪事件，并在有序退出时输出停止事件；事件 MUST 同时进入 stdout 和 `application.log`，包含消费者关联标识和常驻或单轮模式。初始化失败 MUST 输出安全错误事件并维持错误退出，MUST NOT 输出就绪或伪装为正常停止。

#### Scenario: 常驻消费者启动且队列为空
- **WHEN** 常驻消费者成功初始化、完成首轮数据库扫描，队列没有任务
- **THEN** 终端及应用日志均能看到启动和就绪事件，不需要等首个任务才出现日志，空闲轮询不持续输出 INFO

#### Scenario: 单轮空队列退出
- **WHEN** 单轮模式成功初始化并完成一次空队列扫描消费
- **THEN** 启动、就绪、正常停止均可观察，命令及时返回且不制造任务消息

#### Scenario: 初始化依赖失败
- **WHEN** Redis 或数据库初始化操作失败
- **THEN** 启动之后出现固定诊断的错误事件，命令错误退出，不出现就绪或正常停止事件，不记录连接凭证及原始异常正文

#### Scenario: 收到停止信号
- **WHEN** 消费者收到 SIGINT 或 SIGTERM，并按既有规则处理完当前任务后退出
- **THEN** 输出正常停止事件，保持停止新领取和未确认消息可恢复的现有语义

### Requirement: 接收与取得执行权分别记录
消费者 MUST 对收到的任务消息记录接收事件，包含消息标识及可安全解析的任务标识；只有实际获得有效执行权时 MUST 输出任务开始事件。重复、已终态、无效或未取得租约的消息 MUST NOT 被记录为新执行开始；畸形消息 MUST NOT 回显原始字段。

#### Scenario: 合法任务实际开始执行
- **WHEN** 消费者收到合法已提交任务消息并获得执行权
- **THEN** 按顺序输出接收和开始事件，两者可由消费者、消息和任务标识关联

#### Scenario: 重复消息不能开始执行
- **WHEN** 消息指向已终态任务或由其他执行者持有有效租约的任务
- **THEN** 可观察到消息接收，但不出现新的任务开始事件，不改变既有确认、尝试次数或租约规则

#### Scenario: 收到畸形消息
- **WHEN** 消息中的任务标识格式无效或附带任意输入字段
- **THEN** 日志仅使用安全消息元数据，不输出无效任务标识原文或其他消息字段，保持安全确认行为

### Requirement: 任务结果日志遵循持久化与执行所有权边界
消费者 MUST 仅在成功或失败终态实际提交后输出对应结果事件，包含任务关联标识、耗时以及失败时的已安全映射错误码。失去执行权或被拒绝终态写入时 MUST 输出失权诊断，MUST NOT 输出该执行成功或失败的提交事件。任务耗时 MUST 不受展示时间省略小数秒影响。

#### Scenario: 成功结果提交
- **WHEN** 当前有效执行成功保存完整结果、指标及成功终态
- **THEN** stdout 和 `application.log` 均出现关联的成功事件及耗时，不记录结果内容；事件不被误解为消息确认已成功

#### Scenario: 计算失败提交
- **WHEN** 算法错误或输出校验错误经既有规则安全映射并保存失败终态
- **THEN** 输出关联的失败事件和已持久化的安全错误码，不回显原始异常文本

#### Scenario: 执行失去租约
- **WHEN** 心跳报告失租，或计算完成后终态写入因所有权无效被拒绝
- **THEN** 出现关联的失权诊断，不出现当前执行的成功或失败提交事件，不因此确认仍需恢复的非终态消息

#### Scenario: 计算结束但结果没有保存
- **WHEN** 算法已返回但终态事务回滚或保存遭遇基础设施异常
- **THEN** 不输出终态成功事件，不把基础设施异常伪装成业务失败终态

### Requirement: 基础设施诊断不改变任务处理语义
消费者处理期间的数据库、Redis 及租约维护故障 MUST 产生安全的错误或警告事件，存在任务上下文时 MUST 保留关联标识。诊断 MUST 使用固定原因和受控异常类型，MUST NOT 包含异常正文、堆栈、SQL 或连接地址。添加日志 MUST NOT 改变补偿投递、有限重领、租约、终态事务、消息确认和退出码语义；正常心跳 MUST NOT 持续输出 INFO。

#### Scenario: 成功提交后消息确认失败
- **WHEN** 成功终态已提交并产生成功事件，随后 Redis 确认失败
- **THEN** 保留成功结果，另有可关联的 Redis 错误事件，不追加业务失败终态事件，后续重放仍只确认已有终态

#### Scenario: 心跳维护异常
- **WHEN** 租约维护发生数据库异常或执行权失效
- **THEN** 出现安全关联诊断，继续按现有失权规则放弃当前终态写入，不增加新的自动重试或改变退出策略
