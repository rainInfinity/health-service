# Design

## Context

动机及范围见 `proposal.md`。当前 `src/health_service/models/` 已有十二种业务实体和七个迁移；HTTP 只装配账号与资料路由。账号及资料用例已有具体持久化函数、已求值的内部 Schema 和同步事务，通过异步 API 的 `sync_to_async` 调用。`health_inference` 目前只有空包，依赖中没有 Redis 客户端或计算库。

参考旧项目的 `src/models/services/hr_br/main.py` 与 `utils/ppg.py`：输入逻辑名为 `ppg`，CSV 使用毫秒时间戳 `timestampFrame` 和 RGB／YUV 通道，无模型权重。旧实现还存在质检、滤波、呼吸率限幅与默认值；本变更不迁移或评判这些计算规则。旧项目本机的模型制品与采集样本目录为空，不能以此宣称真实算法验收。

当前数据库／架构文档将可靠投递、执行恢复及算法契约归属列为未定事项。本设计选择数据库扫描与租约隔离，实施时更新这些文档，不能把选择描述成现有实现。

## Goals / Non-Goals

**Goals:**

- 应用层持有事务和业务规则；具体持久化模块处理 ORM、已知约束和行锁；API 不持有惰性查询结果。
- 数据库是任务与结果的权威来源；Redis 允许重复消息，不成为执行所有权或结果副本。
- 创建、上传、提交、版本切换和终态写入各有明确的并发边界；恢复后的旧执行者不能覆盖结果。
- 模板与示例可以实际驱动 service 链路，但始终明确非医学用途，正式执行器缺席时不假装已接入。

**Non-Goals:**

- 不通过模拟心率／呼吸率、固定成功返回或未实现的正式执行器满足验收。
- 不增加通用仓储、依赖注入容器、独立结果表、Outbox 表或 Redis 结果队列。
- 不在 Web 进程加载计算资源，不实现批处理调度或多进程扩容；其他范围外事项见提案。

## Decisions

### 1. 保持现有应用与持久化边界

按模型目录、任务输入、任务执行划分用例与具体持久化模块。内部结果使用 Pydantic／dataclass 已求值数据；请求与响应在 HTTP 边界处理驼峰别名。复杂事务继续使用同步 `transaction.atomic()`，由异步入口通过 `sync_to_async` 调用，文件写入及同步 Redis 操作也不占用事件循环。

不逐表增加领域实体或通用仓储接口；任务状态和允许的迁移等独立规则才放进 `domain/`。统一异常映射复用现有 401／403／404／409／422／500 和安全文案；只识别已知唯一约束冲突，不把任意数据库异常转换成输入错误。

### 2. 算法定义来自受控代码注册，示例与正式契约分离

`health_inference` 定义算法元数据、执行输入、执行结果及安全算法异常；`health_service.infrastructure.inference_adapter` 负责从业务版本、存储键和快照准备计算输入。元数据声明所需文件、制品、资料字段、参数校验、结果校验和示例属性。数据库仅保存稳定 `algorithm_key` 与版本 `params`，不新增 `input_spec` 列，也不导入数据库指定的任意 Python 类。

正式心率／呼吸率模板说明 `ppg` 输入、无权重制品和未来 `hr`／`br` 结果契约，但不注册未实现的正式执行器。可执行示例注册为 `hr_br.example`，没有制品或必填健康资料，使用 Python 标准库读取 CSV，生成实际样本数、信号时长、采样率等诊断。它不输出 `hr`／`br`，完整结果含 `example: true`，模型／任务公开数据含 `isExample: true`；该属性来自注册定义而不是客户端传值。

合成样本放在 `docs/examples/hr-br/ppg.csv`，包含 `timestampFrame`、`avgR`、`avgG`、`avgB`，注明时间戳单位 ms、生成规则及非临床数据。示例要求时间戳严格递增、数值有限、至少两个样本；错误输入返回安全算法失败，不以默认值制造有效结果。示例指标使用独立代码，例如 `example.ppg.sample_count`、`example.ppg.duration_seconds`、`example.ppg.sampling_rate_hz`，不得与未来健康指标混合统计。

运行时以模型版本 ID 缓存可复用执行器，只持有固定参数、制品及资源；输入路径、快照、质检及处理后文件属于逐任务执行数据。缓存不会覆盖已发布配置；仍有渠道引用或未终结任务的版本不卸载，排空后可释放。卸载不删除制品。算法契约出现不兼容变化时注册新标识，不原地改变旧标识对已发布版本的解释。

选择这一路径而非完整迁移 NeuroKit2／ONNX，可把 service 的权限、事务和恢复独立验证；真实数值行为由后续算法变更负责。

### 3. 管理认证与最小模型目录 API

沿用渠道绑定 JWT，增加 `manager` 的密码登录、刷新和登出。签发管理令牌要求账号可用且 `is_staff`；管理 API 每次重新检查渠道与管理权限，刷新也重检权限。管理账号由受控管理命令建立，不增加公开注册或普通用户提权字段。被撤销管理权限的用户仍可撤销自己的有效管理 Refresh，但不能刷新或管理模型；Access 的立即撤销策略不变。

模型目录支持创建模型、创建／读取／更新未发布版本、上传制品、定义指标、设置投影指标、发布和切换渠道版本。发布时校验注册执行器、参数、声明的制品集合与文件存在、指标类型及语义；无制品算法允许零制品。未知算法、仅有模板而无执行器的正式算法不能发布。版本发布后算法标识、参数、制品及投影集合不可变，指标类型／单位发生语义变化时创建新代码。

首次渠道配置以渠道行锁串行化，避免选择记录尚不存在时唯一约束竞态。发布锁版本行，并与制品和指标修改共享这把锁；发布后不允许修改物理制品或从业务入口删除其引用。

HTTP 路由均以 `/api/v1` 为前缀：

| 方法与路径 | 行为 |
|---|---|
| `POST /manager/auth/login`、`POST /manager/auth/refresh`、`POST /manager/auth/logout` | 管理渠道认证 |
| `POST /manager/models` | 创建模型 |
| `GET /manager/models/{model_id}/versions`、`POST /manager/models/{model_id}/versions` | 查询／创建版本 |
| `PATCH /manager/model-versions/{version_id}` | 更新未发布版本的算法标识或参数 |
| `POST /manager/model-versions/{version_id}/artifacts` | multipart `logicalName` 与 `file`，登记制品 |
| `POST /manager/metrics` | 创建数值或布尔指标定义 |
| `PUT /manager/model-versions/{version_id}/metrics` | 设置未发布版本的投影指标集合 |
| `POST /manager/model-versions/{version_id}/publish` | 发布完整版本；对已发布版本重放不改发布时间 |
| `PUT /manager/channels/{channel}/models/{model_id}/selection` | 选择已发布、属于该模型的版本 |
| `GET /{channel}/models` | 普通渠道登录后读取当前可用模型、版本、输入逻辑名与示例标志 |

普通渠道查询不暴露参数、绝对路径或制品下载地址。分页采用 `offset`／`limit`，默认 20、上限 100；顺序稳定，目录按 ID、版本按 ID，任务按创建时间与 ID 倒序。

### 4. 草稿、上传、提交和切换的事务边界

创建草稿固定渠道当前已发布版本。草稿不自动过期。上传先验证账号、渠道、任务归属及输入逻辑名，再锁任务行；只允许 `DRAFT`，完整文件落盘后才新增数据库记录，同名旧选中记录改为未选中，历史记录与文件永久保留。

创建草稿、最终提交和版本切换统一按“渠道行 → 当前版本选择行 → 任务行”加锁，任务按主键稳定顺序；只锁需要的表行，避免关联查询隐式扩大锁范围。缺失配置拒绝创建草稿。上传仅锁任务行，不反向取得渠道锁。提交冻结资料时再锁用户行与资料行，沿用现有资料更新的用户先行锁顺序；缺失资料仅构造空内部结果，不创建数据库记录。

提交在锁内重检版本仍当前、全部声明文件已选中且实际存在，冻结完整资料及提交日期计算的年龄，记录 `submitted_at`，转为 `SUBMITTED`。未填写出生日期时年龄为空，病史未知键仍缺席，身高体重保留明确单位；快照不依赖实时资料后续更改。业务 API 不默认返回姓名、病史等完整快照。算法所需资料在执行前依据该固定版本的契约校验，缺失可记 `INFERENCE.MISSING_PROFILE`；提交不扩展为所有算法资料完整性校验。

切换在同一事务更新当前指针，并将该渠道原版本的全部 `DRAFT` 标为 `FAILED`，写入 `TASK.MODEL_SWITCHED`、完成时间及审计。同版本重选不终止草稿。`SUBMITTED`／`RUNNING` 按自身版本完成，回退不恢复旧失败草稿。并发创建／提交要么在切换前完成，要么观察到新配置，不能漏掉旧草稿。

| 方法与路径 | 行为 |
|---|---|
| `POST /{channel}/tasks` | 接收 `modelId`，创建草稿 |
| `GET /{channel}/tasks` | 本人、当前渠道的分页任务摘要 |
| `GET /{channel}/tasks/{task_id}` | 任务详情、成功结果或安全失败摘要 |
| `POST /{channel}/tasks/{task_id}/files` | multipart `logicalName`、`file`；完整上传后替换选中关系 |
| `POST /{channel}/tasks/{task_id}/submit` | 最终提交；重复提交返回冲突，不刷新快照 |
| `GET /{channel}/tasks/{task_id}/files/{file_id}/download` | 授权读取本任务的历史或当前输入 |
| `GET /{channel}/tasks/{task_id}/outputs/{logical_name}/download` | 授权读取成功结果登记的处理后文件 |

任务创建／上传返回 201，提交和普通查询返回 200；创建与上传均返回完整统一 JSON。跨账号或跨来源渠道的任务／文件访问统一 404，不泄露资源是否存在；有效令牌渠道与路由不符仍遵循现有 403。失败详情和内部异常不向普通用户开放。任务列表只选择摘要字段，不默认载入快照或完整结果。

### 5. 文件写入与数据库不假装原子

原始输入及处理后文件使用 `TASK_DATA_ROOT`，模型制品使用 `MODEL_ARTIFACT_ROOT`。存储适配器生成不可猜测的唯一相对键，不采用客户端文件名构造路径，不覆盖已有文件；读取校验键、解析根目录边界和符号链接逃逸，部署禁止不可信用户修改这些目录。分块写入，拒绝空文件与超限文件，不一次性读取全部上传数据。

上传在目标记录锁内完整落盘再登记；事务失败只删除本请求新写入且未登记的文件，不删除旧文件。进程在落盘与登记之间退出可能留下孤儿文件：当前记录这个风险，不增加自动清理器或暴露孤儿下载。计算输出使用每任务、每执行令牌的独立目录；失败／失租输出不进入权威结果。

处理后文件由计算输出显式声明逻辑名和路径，适配器验证位于本次输出目录且文件存在后转换为相对存储键，写入版本化结果中的 `output_files`。下载只从成功任务已登记的映射取键，不接受请求指定路径。示例当前不产生处理后文件，但保留可验证的输出文件契约；用一次性验证执行器证明下载边界，不能仅测函数转发。

成功文件响应使用 `FileResponse`，不包装 JSON；拒绝或资源缺失沿用统一 JSON 错误。原始健康数据不作为公开静态目录。

### 6. 数据库补偿扫描优先于新增 Outbox

任务提交事务完成后立即尝试发布只含 `task_id` 的 Redis 消息。Redis 超时／连接错误只导致本次发布失败，API 仍返回数据库已接受的提交；任务保持 `SUBMITTED`，下一次扫描补发。未预期的程序错误不作为 Redis 暂时性故障吞掉。

记录 `last_dispatched_at`，仅在发布成功后对仍可派发的任务条件更新，不覆盖其他状态或执行字段。发布成功、时间更新失败会产生重复消息，允许；不能先更新时间再发布。消费者每轮执行有界补发扫描，覆盖未发布／超补发间隔的 `SUBMITTED` 及租约已过期的 `RUNNING`。后者支持未确认消息重领，也可在消息条目不可用时重新驱动数据库任务；不把 Redis 可用性风险转成“保证消息永不丢失”。

扫描设置批量上限、顺序稳定，避免饥饿；多个扫描者可能重复发送，数据库执行令牌负责隔离。选择扫描而非 Outbox 是因为任务本身已有所有权威待执行信息，初期不需要新的业务表和派发状态机；代价是重复消息与有界恢复延迟。

### 7. 执行租约与令牌隔离

任务表增加四个字段：

| 字段 | 类型与含义 |
|---|---|
| `execution_token` | 可空 UUID，每次有效领取产生新令牌；只在 `RUNNING` 存在 |
| `lease_expires_at` | 可空带时区时间，执行所有权到期点；与令牌成对，只在 `RUNNING` 存在 |
| `attempt_count` | 非负整数，默认 0，只在有效领取时增加，不在消息重复／发布失败时增加 |
| `last_dispatched_at` | 可空带时区时间，只记录最近一次成功发布，可在终态保留诊断用途 |

检查约束要求执行字段成对及与 `RUNNING` 状态一致；沿用现有结果、失败与完成时间约束。租约判定与续期使用数据库时间，避免不同进程时钟导致错误抢占。初次执行记录 `started_at`，重领保留第一次开始时间。

领取事务只接受 `SUBMITTED` 或租约已过期 `RUNNING`。领取设置令牌、租约、尝试次数和审计，执行专属输出目录包括令牌。续约、成功与失败写入均要求任务仍 `RUNNING`、令牌匹配且租约未过期；续约不能复活已过期租约。失去所有权时放弃落库，不能确认仍需其他执行者处理的消息。

消费者采用单执行任务加独立心跳的初期模式。健康长任务定期续约；数据库心跳失败时不将任务误判成算法失败，所有权最终由数据库状态判定。恢复者可重算，执行令牌只保证旧结果不能提交，不承诺外部副作用恰好一次；算法本次只允许计算及独立目录写入。

最多执行尝试数默认 3。已经达到上限的过期任务由持有数据库锁的恢复流程写 `TASK.RETRY_EXHAUSTED`，完成时间与安全摘要同时落库；普通算法业务失败直接终结，不自动重试。暂时性数据库／Redis 故障不直接写 `FAILED`；持续基础设施中断导致无法完成租约执行，恢复后仍可能耗尽次数，这是有限重试策略而非基础设施异常直接映射。

新字段迁移兼容现有非运行任务。实施前只读检查是否存在旧 `RUNNING` 记录；若存在，在消费者停止的维护窗口将其租约标为立即过期并赋隔离令牌，保留原开始时间，交由新恢复流程处理，不静默跳过。迁移不改成功结果或删除历史记录。

### 8. 消费、结果持久化和消息确认

独立管理命令 `run_inference` 创建消费组并通过 `XREADGROUP` 领取，用 `XAUTOCLAIM` 重领超过租约时长的未确认消息；重领取得消息不等于取得数据库执行权。数据库仍有有效租约时不重复执行、不确认该消息，等待后续重领。已成功或失败的任务消息直接确认，不修改终态。引用不存在任务或畸形任务标识的消息属于不可执行消息，安全确认，不把异常内容记录为健康结果。

正常输出先按固定版本结果契约校验，再提取实际存在且版本选定的指标；数值必须有限，布尔不得按 Python 整数误判，类型及单位语义与指标定义一致。完整结果、指标行和 `SUCCEEDED` 在同一事务写入，清空租约与令牌。缺席指标不产生行，不以零／false 补齐；详情读取完整结果，不反向拼接指标。

失败代码按阶段分为 `TASK.*`、`INFERENCE.*`、`RESULT.*`，例如 `TASK.MODEL_SWITCHED`、`TASK.RETRY_EXHAUSTED`、`INFERENCE.INVALID_INPUT`、`INFERENCE.MISSING_PROFILE`、`INFERENCE.EXECUTION_ERROR`、`RESULT.INVALID_OUTPUT`。摘要使用固定安全文案，详情仅保存允许的结构化诊断，不保存原始健康数据、绝对路径、异常正文或堆栈。普通任务详情不返回诊断详情。

只有终态事务完成或确认消息不可执行后才 `XACK`。终态提交后确认失败不撤销结果，后续重复消息只确认；数据库提交失败不确认，租约过期后恢复。关闭信号停止新领取，不能把未完成任务假写终态；进程退出后由数据库租约与未确认消息恢复。

命令支持 `--consumer` 和 `--once`；默认常驻。`--once` 进行一轮有界扫描与消费，无消息即退出，有消息则完成本批，用于实际 smoke 和运维。Stream 本批不自动裁剪／删除：避免清理误删仍需重领的消息，开发文档明确其磁盘增长风险。

### 9. 配置与验证基线

新增配置均遵循已有“进程变量优先于可选 `.env`，模板不参与运行”规则，并同步 `.env.template`：

| 配置 | 初期默认与约束 |
|---|---|
| `TASK_DATA_ROOT`、`MODEL_ARTIFACT_ROOT` | 项目根目录相对 `var/tasks`、`var/model-artifacts`，支持绝对路径，进程需有访问权限 |
| `MAX_UPLOAD_BYTES` | 52428800，正整数；拒绝空文件和超限上传 |
| `REDIS_URL` | `redis://127.0.0.1:6379/0`，可配置；带密码 URL 不进入日志 |
| `INFERENCE_STREAM`、`INFERENCE_GROUP` | `health:inference`、`health-inference`，非空 |
| `INFERENCE_LEASE_SECONDS` | 60，正数 |
| `INFERENCE_HEARTBEAT_SECONDS` | 10，正数且小于租约的三分之一 |
| `INFERENCE_DISPATCH_INTERVAL_SECONDS` | 30，正数；补发间隔不是执行超时 |
| `INFERENCE_MAX_ATTEMPTS` | 3，正整数 |
| `INFERENCE_POLL_MILLISECONDS` | 1000，正整数；命令无消息时的等待上限 |

使用 `redis-py` 与 `uv` 锁文件，不引入旧计算依赖。本地验证使用隔离测试数据库、唯一 Stream／消费组和临时存储根目录，不能清空本机 Redis 或用户数据。需要实际证明：示例提交完成、输入诊断值准确、版本切换并发、冻结资料、私有下载、发布失败后补发、执行中退出后重领、落库后未确认重放、失租旧令牌无法写入，以及结果与指标回滚一致。永久测试覆盖用户可见行为和状态边界，示例 smoke 不等于医学准确性证明。

## Risks / Trade-offs

- [单进程执行与全渠道行锁限制吞吐] → 初期优先正确性，稳定锁顺序防止切换漏草稿；后续依据负载再缩小锁粒度或扩容，不提前加入合批。
- [数据库扫描与至少一次投递产生重复消息] → 领取事务、有效租约和执行令牌隔离；终态幂等确认，不承诺计算只运行一次。
- [进程崩溃可能留下孤儿输入或失败输出] → 唯一键与独立执行目录、不登记不下载；本批不自动删除既有健康文件。
- [上传期间持有任务行锁] → 分块写入和上传限额控制占用；避免为提前优化引入未完成上传的新状态或表。
- [完整资料快照包含姓名和病史、长期保留] → 不默认对外返回，不入日志，访问绑定归属；数据保留及删除政策不能以技术缓存策略代替。
- [示例被误认为真实健康预测] → 独立算法标识、示例字段、非健康指标代码、文档说明；未实现正式算法不能发布。
- [租约失效后旧计算仍可能运行] → 禁止共享输出目录和权威写入，确保算法无其他外部业务副作用。
- [Stream 无自动裁剪导致增长] → 显式告知部署限制；本批不以不安全裁剪换取有限存储。

## Migration Plan

1. 实施时先增加契约、任务执行字段与迁移、配置及 `.env.template`，同步数据库文档；不改动现有账号／资料 API。
2. 部署前检查并处理旧 `RUNNING` 记录；迁移与 Web／消费者变更在一致维护窗口完成。备份数据库和文件目录，不删除历史任务或输入。
3. 配置 Web 与独立消费者访问同一文件根目录、数据库和 Redis；先发布明确示例版本并为一个普通渠道配置当前版本，使用受控管理账号完成端到端验证。
4. 开启常驻消费者，再开放任务提交入口；停用时先停止新提交再停消费者，未终结任务与消息保留。
5. 回滚业务代码前停止新提交与消费者；新增数据库列可暂留，不撤销为成功任务已写入的结果和文件。只有在确认不丢失恢复状态且相关数据已经处置后才反向迁移，不能自动回滚删除执行字段。
