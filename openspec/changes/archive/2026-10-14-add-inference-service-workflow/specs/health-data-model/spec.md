# Spec Delta

## ADDED Requirements

### Requirement: 任务持久化执行与补发信息
系统 MUST 为任务保留可空 UUID 执行令牌、可空租约到期时间、默认零的非负执行尝试次数及可空最近成功发布时间；这些字段与现有任务归属、快照、状态及结果共存，不增加平行结果或消息权威表。

#### Scenario: 新建草稿
- **WHEN** 创建尚未提交或执行的草稿
- **THEN** 执行令牌、租约和最近成功发布时间为空，执行尝试次数为零，既有结果与业务时间空值语义保持不变

#### Scenario: 有效执行领取
- **WHEN** 任务取得一次有效执行权
- **THEN** 新令牌及租约与运行状态持久化，尝试次数增加一次，发布次数不替代执行次数

### Requirement: 租约字段与运行状态一致
系统 MUST 保证执行令牌和租约到期时间成对存在，只有 `RUNNING` 任务保留二者；运行中任务必须具有这两个字段，进入成功或失败终态时必须清空二者。尝试次数不得小于零。

#### Scenario: 无租约运行任务
- **WHEN** 写入运行中任务但缺少执行令牌或租约到期时间
- **THEN** 数据库拒绝不完整执行记录，不能保存无法判定恢复资格的运行状态

#### Scenario: 终态残留执行权
- **WHEN** 写入成功或失败任务但仍保留执行令牌或租约
- **THEN** 数据库拒绝该记录，终态写入必须同时结束执行所有权

#### Scenario: 非法执行次数
- **WHEN** 尝试保存负数执行尝试次数
- **THEN** 数据库拒绝该值，不改变任务状态或结果

### Requirement: 执行扩展不破坏既有历史与审计
系统 MUST 在增加执行字段时保留已有账号、资料、任务、输入和结果，继续维护任务状态更新的审计时间与稳定操作人；既有未恢复运行记录必须进入明确的可恢复状态，不得静默删除、跳过或伪造成功。

#### Scenario: 已完成任务迁移
- **WHEN** 对已有成功或失败任务应用执行字段扩展
- **THEN** 原完整结果、指标、失败信息及历史文件不改变，新增执行所有权字段保持为空

#### Scenario: 存在旧运行记录
- **WHEN** 部署前检查发现没有新执行字段的旧运行记录
- **THEN** 在停止旧执行者的维护流程中为其建立过期恢复信息，保留版本、快照和首次开始时间，交由新执行流程处理

#### Scenario: 批量更新状态
- **WHEN** 后台领取、续约、切换或终结任务使用批量更新
- **THEN** 修改时间与稳定操作人随实际更改明确维护，不依赖 HTTP 请求上下文或可变用户名
