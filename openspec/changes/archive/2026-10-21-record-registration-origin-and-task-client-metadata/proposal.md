# Proposal

## Why

当前账号注册接口已经能从路径识别普通渠道，但未将首次注册渠道持久化；推理任务也没有保存提交时的客户端自定义上下文。记录这两类来源信息可支持任务追溯与排查，并为需要客户端上下文的算法提供可选输入，同时不把它变成所有算法的前置条件。

## What Changes

- 为账号记录首次注册所用的普通 API 渠道；来源由服务端路由确定，创建后不因后续登录渠道变化而改写。
- 允许推理任务最终提交时附带可选客户端元数据，并与任务提交快照一起持久化。
- 将已提交的客户端元数据作为可选推理上下文提供给算法；未提供时不阻止提交或执行。
- 不新增任务元数据查询 API，不将元数据加入普通任务响应或日志；排查通过授权运维数据库工具完成。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `user-auth`：明确并记录账号首次注册所用的普通渠道。
- `user-persistence`：在账号创建时持久化不可变的注册渠道来源。
- `inference-tasks`：最终提交接受并冻结可选客户端元数据。
- `inference-algorithms`：将可选客户端元数据纳入算法输入契约，缺失不构成全局必需输入。

## Impact

预期影响账号注册 API 与持久化、推理任务提交 API 与任务持久化、推理适配器及纯算法输入类型，并需要数据库迁移和行为测试。客户端元数据仍是客户端提供的非可信数据；本变更不提供设备身份认证，也不开放读取接口。本提案仅记录需求范围，不修改业务代码、测试或普通开发文档。
