# Design

## Context

参见 [proposal.md](proposal.md) 的动机。注册入口已识别并校验路径渠道，但注册用例未接收该值；任务最终提交当前没有请求体，只在事务中冻结健康资料。现有任务记录没有客户端元数据字段，纯推理输入也没有客户端上下文。普通用户任务响应不暴露内部快照，当前没有管理端任务查询接口。

## Goals / Non-Goals

**Goals:**

- 保存每个新账号首次注册所用的普通 API 渠道，并保留历史账号的来源未知状态。
- 在任务最终提交时接收可选客户端元数据，与提交状态和资料快照一致地冻结。
- 将任务保存的可选元数据交给推理执行器；未提供时算法仍可按既有输入契约运行。
- 保持现有客户端无提交请求体时的兼容性，并保持普通响应、查询接口和日志不含元数据。

**Non-Goals:**

- 证明设备实际品牌、型号或操作系统；路径渠道和客户端自报元数据都不是可信设备身份。
- 让所有算法依赖或消费客户端元数据，或将它并入健康资料快照。
- 新增管理端／普通用户元数据查询 API、广告来源归因或推广活动标识。

## Decisions

### 1. 注册来源使用现有渠道关系

账号记录首次注册的普通渠道，来源由已校验的 `/{channel}/auth/register` 路径传入注册用例；注册请求体不能覆盖它。复用已有渠道实体，避免账号表再维护一套可漂移的渠道字符串。注册事务需要确保对应普通渠道记录存在，并与账号及空资料原子创建。来源创建后只读，后续登录不更新。

新增关系对历史账号保持 `null`，因为现有数据没有可验证的注册渠道；迁移不得从任务渠道、最近登录渠道或当前渠道推测来源。新注册必须写入有效普通渠道。注册和本人账号的公开回复保持既有结构。

替代方案是把渠道值作为账号上的自由字符串。未采用：渠道实体已用于任务归属和模型选择，复用可保持一致性；代价是注册路径需要在事务内取得或创建渠道记录。

### 2. 提交时冻结独立的可选 JSON 对象

最终提交接受可选 JSON 请求体字段 `clientMetadata`。字段缺省或为 `null` 表示没有元数据；非空值必须是对象，键保持扩展性，值限于 JSON 数据。原有完全不带请求体的提交继续等价于缺省元数据。客户端元数据作为独立任务字段保存，不塞入 `profile_snapshot`，也不在草稿创建、文件上传或提交失败时留下部分数据。

元数据、健康资料快照、提交时间和任务状态在同一提交事务中写入；提交成功后不允许修改。任务保存值是恢复执行时使用的唯一来源，不重新读取 HTTP 请求或实时客户端状态。替代方案是在任务 `addition` 或资料快照内混存。未采用：前者没有现存契约，后者会混淆健康资料与客户端上下文边界。

服务端只持久化该对象，不提供查询 API，不将它加入普通任务摘要／详情或结构化日志。排查通过授权运维数据库工具完成。客户端可控内容按非可信输入处理；算法不能将其当成授权或设备真实性凭证。请求继续受服务现有 HTTP 请求体限制，不增加独立环境配置项。

### 3. 通过纯计算输入可选传递

持久化适配器从任务快照读取元数据，并把它作为独立的可选字段交给 `InferenceInput`；缺省时为 `None`。它不进入 `profile`，不参与全局必需资料校验。算法可以忽略该字段；消费字段的算法必须在自身契约中声明键的含义、类型校验和缺失时行为。扩展元数据中的未知键仍可留档，但算法不得假设自己理解它们。

如果某算法的输出依赖特定元数据值，该依赖属于算法稳定输入契约；改变其解释必须沿用算法契约的版本化规则，保证已提交任务的保存快照可用于恢复执行。替代方案是只存不传，等真实算法出现后再改接口。未采用：用户已确认算法可能需要该数据，增加可选传递可避免遗漏任务快照与执行输入之间的链路；目前算法不使用它时行为不变。

### 4. 增量迁移并保留旧客户端行为

数据库变更只新增可空的注册来源关系和任务 JSON 元数据字段。历史账号来源及既有任务元数据保持 `null`，不做虚构回填。先部署兼容旧请求的服务版本；不带提交请求体的旧客户端继续提交任务，新客户端可附带元数据。不存在依赖新查询 API 的前端迁移。

回滚应用版本时保留新增列和已保存值；只有确认无需保留数据后才可单独执行删除列的逆向迁移。

## Risks / Trade-offs

- **来源渠道可能被调用者选择或伪造** → 将其定义为“请求注册的 API 渠道”，不解释为实际安装平台或推广归因。
- **任意扩展 JSON 可能意外包含敏感值或大载荷** → 仅将客户端明确提供的元数据保存到受保护任务记录；不回显、不写日志，并沿用服务请求体限制。
- **算法对同一元数据键产生不同解释会影响历史任务恢复** → 消费字段的契约必须归属算法版本；不允许静默改变已发布算法的输入含义。
- **运维查库不如管理页面方便** → 这是当前选定的最小访问范围；若后续需要管理端查看，应另行定义受控任务查询能力。
