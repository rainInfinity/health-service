# Spec Delta

## ADDED Requirements

### Requirement: 最终提交可冻结可选客户端元数据
普通用户最终提交草稿时 MAY 提供可扩展的 JSON 对象 `clientMetadata`。成功提交 MUST 将其作为独立于健康资料的任务快照持久化，并与任务状态转换原子完成；省略或提供 `null` 表示没有元数据，非对象值 MUST 被拒绝。提交后元数据不可修改，普通任务响应、查询接口和日志 MUST NOT 暴露其内容。

#### Scenario: 提交携带客户端元数据
- **WHEN** 用户为合法草稿提交 JSON 对象 `clientMetadata`，且任务其他提交条件均满足
- **THEN** 系统将该对象与健康资料快照一同冻结在任务上，不合并进健康资料，普通任务响应不包含该对象

#### Scenario: 元数据缺省
- **WHEN** 用户提交合法草稿时省略 `clientMetadata` 或将其设为 `null`
- **THEN** 任务正常提交并记录无客户端元数据，缺省值本身不阻止后续推理执行

#### Scenario: 元数据不是对象
- **WHEN** 用户提交 `clientMetadata` 为字符串、数字、数组或其他非对象 JSON 值
- **THEN** 系统拒绝请求，草稿不转为已提交且不保存部分元数据

#### Scenario: 提交事务失败
- **WHEN** 提交事务未能完成任务状态转换
- **THEN** 客户端元数据与健康资料快照均不被部分保存，任务仍遵循原有未提交状态

#### Scenario: 已提交任务再次提交
- **WHEN** 用户对已提交任务再次提交不同客户端元数据
- **THEN** 请求按既有状态冲突规则拒绝，已冻结的元数据保持不变
