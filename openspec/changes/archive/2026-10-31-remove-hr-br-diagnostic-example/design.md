# Design

## Context

见 `proposal.md` 的动机与影响范围。当前算法包初始化时同时注册 `hr_br.example` 和正式 PPG v1；示例执行器只返回输入诊断，并复用正式解析器。仓库十行 CSV 仅用于该诊断执行器，正式 PPG 滤波链不能处理该长度。通用目录与任务契约仍通过算法定义派生 `isExample`，不随单个执行器删除。

## Goals / Non-Goals

**Goals:**

- 删除唯一内置 PPG 诊断执行器及其专用样例，不保留兼容别名或隐式替代。
- 保留正式 PPG v1、通用 `isExample` 响应字段和无效算法标识的现有拒绝路径。
- 让通用服务测试不再依赖已移除的生产算法，同时保留正式算法的真实计算覆盖。

**Non-Goals:**

- 不删除或改写数据库中已有的模型版本、渠道选择或任务记录。
- 不删除通用 `isExample` API/Schema 字段，不引入新的演示算法或替代诊断端点。
- 不改变正式 PPG v1 的输入、质量、推理和输出行为。

## Decisions

1. **直接撤销示例算法注册。** 从内置注册入口移除 `hr_br.example`，删除其实现文件，不保留 alias、fallback 或仅为旧模型版本服务的 shim。目录发布继续走现有 `get_algorithm` 和算法契约校验；已移除标识按未知算法处理。
2. **移除专属数据和诊断导引，保留正式接入指南。** 删除 `docs/examples/hr-br/` 的 CSV 与 README。活跃的模型管理和前端联调文档改用正式 `ppg.active.offline.hr_br.v1`、`hr`/`br` 指标契约及符合滤波前提的调用方输入，不附带一个会被误认为正式输入的短样例。通用请求/响应示例和 `isExample` 字段说明仍保留。
3. **测试按被测边界选择算法。** 目录、提交、租约、消息确认等不验证生理算法的测试使用 `test.*` 测试专用定义；验证输入隔离或实际结果的测试使用正式 PPG v1 及满足其滤波长度要求的合成信号。测试专用定义不进入 `health_inference` 内置注册表，也不复制已删除的样本数／时长／采样率算法。
4. **不迁移持久化版本。** 新部署不删除数据库记录。现存版本若引用 `hr_br.example`，运行时无法解析该算法；发布或查询路径也可能将其视为目录配置错误。部署前需由运维确认渠道不再依赖该标识。恢复旧代码可恢复该标识解析，因为数据库记录不会被改写。

## Risks / Trade-offs

- [已有渠道选择仍指向旧标识] → 新代码无法解析或执行这些版本；部署前确认选择已切换到正式算法。此变更不执行数据库清理或自动迁移。
- [通用流程测试曾依赖短小示例输出] → 使用测试专用契约隔离目录与队列行为；实际 PPG 结果和文件仍由正式算法路径验证。
- [删除打包样例后，前端联调需要自备数据] → 文档明确引用正式算法输入约束，不再把十行诊断数据作为可运行信号。

## Migration Plan

1. 在代码部署前，确认目标数据库中没有仍被渠道选择或待处理任务引用的 `hr_br.example` 版本；如有，先由管理端切换到正式版本，不能删除历史任务。
2. 部署移除注册后的 Web 与消费者代码；不执行 Django schema migration。
3. 验证正式 PPG v1 可发布、提交并执行，且普通目录和任务摘要仍返回 `isExample=false`。
4. 回滚时恢复旧应用代码版本；由于本变更不改写历史数据库记录，旧注册恢复后旧版本可重新解析。
