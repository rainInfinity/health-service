# Spec Delta

## MODIFIED Requirements

### Requirement: 算法注册受控且版本解释稳定
系统 MUST 仅接受受控注册且具有可执行实现的算法标识，注册元数据说明示例属性和输入输出规则；未知或未实现标识不能用于发布可执行版本。不兼容契约变化 MUST 使用新标识，不能改变旧已发布版本的解释。

#### Scenario: 使用未实现正式算法
- **WHEN** 管理人员请求发布只有接口模板而没有真实实现的正式心率／呼吸率算法
- **THEN** 系统拒绝发布，不以示例或空实现替代正式执行器

#### Scenario: 同版本历史任务解释
- **WHEN** 查询或恢复一个已提交固定版本任务，同时系统已增加其他算法版本
- **THEN** 该任务仍使用原标识的输入输出契约，不因新增算法而改变结果含义

#### Scenario: 发布已移除的诊断标识
- **WHEN** 管理人员请求创建或发布使用 `hr_br.example` 的模型版本
- **THEN** 系统将该标识视为未注册算法并拒绝，不提供诊断执行器或将其路由到正式 PPG v1

### Requirement: 质量拒绝以受控原因表达
独立计算契约 MUST 允许算法通过受控原因及对应的类型化明细报告质量拒绝，而不要求所有算法计算分数。首批原因 MUST 包括 `LOW_SCORE` 和 `NO_VALID_SIGNAL`；后者只表示算法依据自身明确规则确认没有可用信号，明细为 `null`。未执行质检 MUST NOT 被解释为质量通过或默认满分。

#### Scenario: 报告有评分的质量拒绝
- **WHEN** 算法实际得到分数 40、通过阈值 70，并据此拒绝继续计算
- **THEN** 拒绝原因是 `LOW_SCORE`，明细包含本次实际分数和阈值

#### Scenario: 报告不依赖评分的质量拒绝
- **WHEN** 算法依据自身明确规则判定没有可用信号，但没有计算质量分数
- **THEN** 可以报告 `NO_VALID_SIGNAL` 且明细为 `null`，不要求或补造分数与阈值

#### Scenario: 算法没有执行质量检查
- **WHEN** 一个已注册算法没有执行质量检查
- **THEN** 系统不为其生成默认质量通过、默认 100 分或虚构的质量拒绝

### Requirement: 示例身份不可由客户端隐藏
系统 MUST 根据算法定义的 `isExample` 字段在可用模型、任务摘要和任务详情中公开身份；客户端参数、模型名称或版本名称 MUST NOT 改变算法定义的身份。

#### Scenario: 将示例版本命名为正式版本
- **WHEN** 算法定义将 `isExample` 设置为 `true`，但模型名称不含示例标识
- **THEN** 模型及任务仍返回 `isExample=true`，名称不能掩盖非临床用途

## REMOVED Requirements

### Requirement: 示例执行返回真实输入诊断而非健康数值
**Reason**: `hr_br.example` 不再作为产品算法注册；正式 PPG v1 已提供真实计算契约，独立诊断执行器只会继续扩大可发布算法面。
**Migration**: 不再创建或发布该标识的版本。需要心率／呼吸率结果时使用 `ppg.active.offline.hr_br.v1`，并遵守其正式输入要求。

### Requirement: 合成示例数据可重复使用且不含真实健康资料
**Reason**: 十行合成文件仅服务于已移除的诊断执行器，长度不足以运行正式 PPG 滤波链，继续随仓库提供会造成用途混淆。
**Migration**: 不再提供该专用样例。验证正式算法时使用满足其采样率与滤波长度要求的合成测试输入或合规采集输入。
