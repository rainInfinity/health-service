# 提案

## 背景

当前服务未配置应用请求日志或异常关联信息；用户认证与健康资料接口启用后，仅凭客户端提示难以排查故障，也不能为排查而输出密码、令牌或病史。旧项目提供服务日志与按天轮转，但其请求上下文、IP 获取和解析回复体的方式不适合作为新 ASGI 服务的直接实现。

## 变更内容

- 为 Web API 请求生成服务端请求标识，贯通响应体中的 `requestId`、`X-Request-ID` 响应头、请求完成日志和未预期异常日志；日志能力提供上下文，统一回复提案负责将标识呈现给客户端。
- 记录结构化的请求结果：时间、级别、请求标识、方法、路由模板、普通渠道、HTTP 状态、可取得的业务错误码、耗时及鉴权后的用户 ID；异常仅在内部日志中按相同标识记录用于排查的堆栈，避免同一错误重复记录。配置适用于 ASGI 并避免多请求上下文串扰。
- 禁止记录请求／响应正文、密码、Access／Refresh Token、Cookie、手机号和健康资料；不信任未经配置验证的代理转发 IP，也不为取得业务码解析完整回复体。日志内容与外部通用错误文案分离。
- 优先采用标准输出、由运行环境负责收集及轮转，避免直接沿用旧项目的进程内定时滚动文件；是否必须内建本地文件、日志保存期限及部署采集方式留待后续设计确认。未来独立推理进程可复用基础日志配置，但本次不创建尚不存在的推理命令或假运行记录。

## 能力

### 新增能力

- `api-request-logging`：API 请求和内部异常具备安全、可关联、适用于异步服务的结构化日志，敏感数据不因正常访问或故障处理进入日志。

### 调整能力

无；现有 `service-bootstrap` 只规定服务的启动与安全配置，不要求请求日志或请求关联标识。

## 影响

后续实施涉及 `src/config` 的 Django／Uvicorn 日志配置与 ASGI 请求入口，以及 API 鉴权、错误处理向日志上下文提供的安全字段；若新增日志级别等环境配置，应更新 `.env.template`，并在 `docs/development.md` 说明本地查看方式。`unified-api-responses` 使用本变更提供的 `requestId`，`user-account-api` 的身份事件遵循脱敏规则；需分别验证匿名与鉴权请求、并发请求隔离、异常关联及敏感信息未进入日志。
