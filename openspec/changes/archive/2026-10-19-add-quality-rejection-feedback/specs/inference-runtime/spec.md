# Spec Delta

## ADDED Requirements

### Requirement: 质量拒绝只保存受控失败信息
系统 MUST 仅将符合算法质量契约的明确拒绝映射为 `INFERENCE.QUALITY_REJECTED`，保存受控原因及白名单明细，并由服务生成原因对应的固定安全摘要。系统 MUST NOT 从异常正文提取原因或数值，也不得将原始信号、健康资料、堆栈或本地路径混入质量拒绝信息；普通失败继续不保存任意异常详情。

#### Scenario: 保存合法低分拒绝
- **WHEN** 当前执行报告合法 `LOW_SCORE` 拒绝及实际分数和阈值
- **THEN** 失败记录保留原因和这两个数值，摘要来自受控映射，不使用算法自定义异常正文

#### Scenario: 保存无评分拒绝
- **WHEN** 当前执行报告合法 `NO_VALID_SIGNAL` 拒绝
- **THEN** 失败记录保留该原因且质量明细为 `null`，不补分数或阈值

#### Scenario: 仅伪造质量错误码
- **WHEN** 一个普通计算错误只声明 `INFERENCE.QUALITY_REJECTED`，但没有合法的受控质量拒绝信息
- **THEN** 系统记录通用 `INFERENCE.EXECUTION_ERROR` 和安全摘要，不保存或公开质量明细

#### Scenario: 质量拒绝信息不符合契约
- **WHEN** 当前执行提供未知原因、原因与明细不匹配或非法评分
- **THEN** 系统按通用执行失败处理，不生成质量结论，不保留无效明细或原始异常正文

#### Scenario: 输出质量拒绝日志
- **WHEN** 质量拒绝终态已经提交，消费者记录既有失败事件
- **THEN** 日志保留原有安全关联字段和实际错误码，不新增原因、评分、阈值或其他质量明细

### Requirement: 质量拒绝原子终结为失败
系统 MUST 在同一事务保存质量拒绝的原因、明细、安全摘要、失败码、完成时间和 `FAILED` 状态，并清空执行令牌与租约。质量拒绝 MUST NOT 保存成功结果、指标投影或权威输出文件，不新增任务状态，也不将失败诊断放入成功结果。

#### Scenario: 合法质量拒绝提交
- **WHEN** 有效执行的质量拒绝事务成功提交
- **THEN** 任务为 `FAILED`，失败信息完整，完成时间已设置，执行令牌和租约为空，结果为空且没有成功指标或可下载的权威输出

#### Scenario: 保存质量拒绝时数据库故障
- **WHEN** 保存质量拒绝的事务发生数据库错误并回滚
- **THEN** 不留下部分质量明细或失败终态，不把数据库错误再次改写为质量拒绝，也不确认仍需恢复的消息

### Requirement: 质量拒绝沿用执行所有权与恢复边界
系统 MUST 仅允许当前匹配且未过期的执行权保存质量拒绝，并在观察到持久化终态后确认消息。质量拒绝终态 MUST NOT 因重复投递而重新执行、消耗新的执行次数或被迟到结果改写；重新采集属于新任务，不自动重跑已拒绝的同一输入。

#### Scenario: 过期或旧令牌报告质量拒绝
- **WHEN** 执行令牌不匹配或租约已过期，旧执行尝试提交质量拒绝
- **THEN** 提交被拒绝，不改变任务及失败明细，也不据此确认仍需恢复的非终态消息

#### Scenario: 旧拒绝晚于新执行完成
- **WHEN** 旧执行失去所有权后报告质量拒绝，新执行已经提交成功或失败终态
- **THEN** 新执行的终态及其结果或失败信息保持不变

#### Scenario: 质量拒绝落库后确认失败
- **WHEN** 质量拒绝事务已提交，但消费者退出或消息确认暂时失败
- **THEN** 质量拒绝保持为终态，后续重放只确认已有终态，不重新计算或覆盖原原因和明细
