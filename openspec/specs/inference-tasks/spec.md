# inference-tasks Specification

## Purpose

为普通渠道用户提供从确定模型版本的草稿、独立输入上传到冻结资料并最终提交的任务业务契约，明确并发修改、资源归属、结果详情与历史文件的边界，使计算执行只依赖提交时固定的数据。

## Requirements

### Requirement: 本人任务同时绑定账号和来源渠道
系统 MUST 根据有效 Access 确定提交账号和来源渠道，不接受请求指定其他用户；查询、上传、提交及下载 MUST 同时检查任务归属账号和来源渠道，越权资源访问返回资源不存在，不泄露资源存在性。

#### Scenario: 访问其他账号任务
- **WHEN** 用户请求另一账号任务的详情、文件上传、提交或下载
- **THEN** 系统返回资源不存在，不读取或修改其他账号任务的健康数据

#### Scenario: 同账号跨来源渠道访问
- **WHEN** 同一账号持有 wxapp Access，但请求其 android-cn 来源任务的 wxapp 路径
- **THEN** 系统不返回该任务，账号相同不能绕过任务来源渠道边界

#### Scenario: 请求伪造用户归属
- **WHEN** 创建任务请求包含未声明的用户或管理权限字段
- **THEN** 系统拒绝输入，不据此改变任务归属

### Requirement: 创建草稿固定渠道当前版本
系统 MUST 仅根据该渠道当前选择的已发布版本创建 `DRAFT`，记录固定版本及归属，尚不冻结资料或设置提交时间；未配置可用模型时不得创建任务。草稿 MUST 不因时间经过自动失效。

#### Scenario: 为可用模型创建草稿
- **WHEN** 用户为当前渠道已配置的模型创建任务
- **THEN** 返回固定该渠道当前版本的草稿，包含示例标志，提交时间和资料快照仍为空

#### Scenario: 无可用版本
- **WHEN** 用户请求未配置给该渠道的模型或不可用版本
- **THEN** 系统拒绝创建，不允许客户端指定任意执行版本绕过渠道选择

### Requirement: 只有草稿允许上传声明输入
系统 MUST 只在本人当前渠道的草稿中接收算法声明的输入逻辑名，完整上传后登记有效文件；同名重传新增记录并只选中新文件，旧记录与物理文件继续保留。已提交、运行或终态任务 MUST 不允许上传或替换。

#### Scenario: 同名重传保留历史
- **WHEN** 草稿中已有选中 ppg 文件，用户成功重传同名完整文件
- **THEN** 新文件成为唯一选中输入，旧文件和记录仍可按授权规则读取

#### Scenario: 未声明输入或非草稿上传
- **WHEN** 请求上传未知逻辑名，或向已提交／失败任务上传
- **THEN** 系统拒绝操作，不创建有效输入记录，不改变现有选中关系

#### Scenario: 上传与提交并发
- **WHEN** 同一草稿的最后一次上传与最终提交并发发生
- **THEN** 提交使用完整且已经登记的选中输入，提交完成后上传不能再改变这组输入；不得引用未完成上传

### Requirement: 最终提交固定输入和完整健康资料
系统 MUST 在最终提交时重检任务为草稿、渠道仍选择任务固定版本、所需文件全部选中且可读取，并冻结完整当前健康资料及提交时年龄；通过检查后才记录提交时间并变为 `SUBMITTED`。提交不提前执行算法内容质检或要求所有算法资料均完整。

#### Scenario: 冻结当前资料
- **WHEN** 用户提交具有完整选中文件的合法草稿，随后修改姓名、病史、出生日期或测量值
- **THEN** 已提交任务的完整快照和年龄保持提交时值，后续执行不读取实时资料替换快照

#### Scenario: 资料尚未填写
- **WHEN** 用户没有资料记录或出生日期，在具备所需文件的情况下提交
- **THEN** 提交可以冻结空资料，年龄为空，缺席病史标记保持未知，不为读取快照创建资料记录

#### Scenario: 缺少有效文件或版本已经切换
- **WHEN** 必需逻辑名没有选中文件、实际文件不存在，或固定版本已不再是渠道当前版本
- **THEN** 任务不能转为已提交，不制造提交快照或向计算进程发送新的有效任务

### Requirement: 最终提交不可重复或改写
系统 MUST 拒绝已提交、运行中或终态任务的再次提交，不能重新冻结资料、选择不同输入、重置失败或改变固定版本；任务执行恢复属于后台流程而非用户重新提交。

#### Scenario: 重复提交
- **WHEN** 同一任务的两个提交请求并发或先后到达
- **THEN** 至多一个请求成功完成草稿到已提交的转换，其余返回冲突，不改写首个快照与提交时间

#### Scenario: 重新提交失败任务
- **WHEN** 用户请求再次提交失败任务
- **THEN** 系统拒绝状态重置，原失败和历史输入保留；新业务尝试需要新建草稿

### Requirement: 提交已接受不因消息发布暂时失败撤回
系统 MUST 以数据库提交是否成功决定任务是否已接受；数据库提交后消息发布暂时失败时仍返回已接受的任务状态，保留快照和选中输入，供后台补发，不诱导客户端通过重建或重提交解决消息故障。

#### Scenario: Redis 暂时不可达
- **WHEN** 任务已成功变为已提交，但即时发布消息遇到连接失败或超时
- **THEN** 提交仍返回成功，任务保持已提交，后续投递补偿可以驱动它执行

### Requirement: 列表与详情区分摘要和权威结果
系统 MUST 提供本人当前渠道的有界分页任务摘要及任务详情，摘要包含状态、固定版本、业务时间和 `isExample`，不默认返回完整结果或资料快照；成功详情读取该任务的权威完整结果，不从指标反向拼装或重新执行算法。

#### Scenario: 查询完成任务
- **WHEN** 用户读取自己成功任务的详情
- **THEN** 系统返回该固定版本解释的完整保存结果与示例标志，不触发计算，也不混入实时资料

#### Scenario: 查询列表
- **WHEN** 用户查询合法分页的本人任务列表
- **THEN** 系统按创建时间和任务 ID 的稳定倒序返回不超过请求上限的摘要，不载入大结果作为默认列表内容

### Requirement: 普通用户只看到安全失败摘要
系统 MUST 在失败详情中向普通用户返回稳定失败代码、安全摘要和完成时间，并仅允许额外公开符合质量拒绝契约的 `qualityFailure`。系统 MUST NOT 直接公开内部诊断详情、异常堆栈、原始输入、完整健康资料快照或本地绝对路径；类型化质量信息不构成开放任意 `failureDetail` 的许可。

#### Scenario: 读取计算或结果失败
- **WHEN** 用户查询具有内部失败诊断的本人任务
- **THEN** 返回安全失败码及固定摘要，仅在满足质量拒绝契约时额外返回白名单质量信息，不把诊断中的内部字段直接序列化给用户

### Requirement: 质量拒绝详情按原因公开明细
本人任务详情 MUST 提供可空的 `qualityFailure`。合法质量拒绝的该对象 MUST 含稳定原因码 `reason` 和对应的 `details`；`LOW_SCORE` 的明细仅公开实际 `score`、`threshold`，`NO_VALID_SIGNAL` 的明细为 `null`。质量拒绝任务仍为 `FAILED`，`result` 为 `null`；详情查询成功仍使用 HTTP 200 和外层业务码 `OK`。

#### Scenario: 查看低分拒绝
- **WHEN** 用户成功查询本人当前渠道的合法 `LOW_SCORE` 质量拒绝任务
- **THEN** 详情返回 `INFERENCE.QUALITY_REJECTED`、安全提示和 `qualityFailure`，其中原因是 `LOW_SCORE`，明细为本次实际分数及阈值，查询不重新计算

#### Scenario: 查看无评分拒绝
- **WHEN** 用户成功查询本人当前渠道的合法 `NO_VALID_SIGNAL` 质量拒绝任务
- **THEN** 详情返回该原因且 `details` 为 `null`，不提供虚构分数或默认阈值

### Requirement: 质量信息只从合法失败记录投影
系统 MUST 只在任务为 `FAILED`、失败码为 `INFERENCE.QUALITY_REJECTED` 且原因及所需明细合法时投影非空 `qualityFailure`；其余情况 MUST 返回 `null`。投影 MUST 显式选择允许公开的字段，历史记录缺失或损坏不得使详情查询失败，也不得补造原因、分数或阈值。

#### Scenario: 查询其他状态或普通失败
- **WHEN** 用户查询草稿、已提交、运行、成功任务或普通失败任务
- **THEN** `qualityFailure` 为 `null`；即使普通失败的内部诊断含类似质量字段，也不将其解释为质量拒绝

#### Scenario: 查询缺少或损坏质量明细的历史失败
- **WHEN** 质量拒绝记录没有质量信息、原因未知、原因与明细不匹配、缺少必需数值或数值非法
- **THEN** 详情正常返回已有安全失败摘要，`qualityFailure` 为 `null`，不尝试重新执行或补齐诊断

#### Scenario: 内部质量诊断附带私有字段
- **WHEN** 合法质量原因及明细之外还存在路径、原始数据或其他未声明诊断键
- **THEN** 详情仅投影该原因允许的字段，响应不包含这些额外字段或其内容

#### Scenario: 读取任务列表
- **WHEN** 用户查询本人当前渠道的任务列表
- **THEN** 系统维持摘要响应，不加载或返回质量拒绝明细

#### Scenario: 越权读取质量拒绝
- **WHEN** 用户查询其他账号或其他来源渠道的质量拒绝任务
- **THEN** 系统沿用任务归属规则返回资源不存在，不泄露原因、明细或任务存在性

### Requirement: 最终提交可冻结可选客户端元数据
普通用户最终提交草稿时 MAY 提供可扩展的 JSON 对象 `clientMetadata`。成功提交 MUST 将其作为独立于健康资料的任务快照持久化，并与任务状态转换原子完成；省略或提供 `null` 表示没有元数据，非对象值 MUST 被拒绝。提交后元数据不可修改，普通任务响应、查询接口和日志 MUST NOT 暴露其内容。

#### Scenario: 提交携带客户端元数据
- **WHEN** 用户为合法草稿提交 JSON 对象 `clientMetadata`，且任务其他提交条件均满足
- **THEN** 系统将该对象与健康资料快照一同冻结在任务上，不合并进健康资料，普通任务响应不包含该对象

#### Scenario: 元数据缺省
- **WHEN** 用户提交合法草稿时省略 `clientMetadata` 或将其设为 `null`
- **THEN** 任务正常提交并记录无客户端元数据，缺省值本身不阻止后续推理执行

#### Scenario: 元数据不是对象
- **WHEN** 用户提交 `clientMetadata` 为字符串、数字、数组或其他非对象 JSON 值
- **THEN** 系统拒绝请求，草稿不转为已提交且不保存部分元数据

#### Scenario: 提交事务失败
- **WHEN** 提交事务未能完成任务状态转换
- **THEN** 客户端元数据与健康资料快照均不被部分保存，任务仍遵循原有未提交状态

#### Scenario: 已提交任务再次提交
- **WHEN** 用户对已提交任务再次提交不同客户端元数据
- **THEN** 请求按既有状态冲突规则拒绝，已冻结的元数据保持不变
