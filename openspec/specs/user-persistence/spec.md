# user-persistence Specification

## Purpose

为账号注册和当前健康资料提供可独立于 HTTP 使用的数据访问契约，使应用调用方依赖明确的内部结果、事务一致性和错误边界，避免资料缺失、并发首次填写或按键更新造成孤立账号、重复资料及已提交数据丢失。

## Requirements

### Requirement: 已求值的内部账号与资料结果
账号注册及资料读写的内部接口 MUST 返回仅包含所需字段的已求值数据，不要求调用方持有 HTTP 请求或数据库模型对象，不在调用方读取结果字段时再次访问数据库；已定义字段 MUST 使用内部下划线命名，结果不得包含密码或权限等非必要账号字段。

#### Scenario: 消费注册结果
- **WHEN** 应用调用方完成账号注册并读取返回结果
- **THEN** 可以直接获得账号 ID 与用户名，而无需 HTTP 请求、数据库模型或额外查询，且不能从该结果获得密码和权限字段

#### Scenario: 消费已有资料结果
- **WHEN** 应用调用方读取已有资料并在数据访问操作结束后消费结果字段
- **THEN** 可以直接获得资料值，日期与精确测量值保持其含义，已定义病史键使用下划线命名，消费结果不再触发数据库查询

### Requirement: 注册账号与资料的原子创建
系统 MUST 将普通账号和对应空健康资料作为一次原子注册操作保存；任意一步失败时不得遗留本次注册创建的账号或资料。

#### Scenario: 注册成功
- **WHEN** 有效普通账号注册完成
- **THEN** 账号与一份以账号 ID 为主键的空资料同时存在，密码保持哈希存储，手机号未绑定且不授予管理权限

#### Scenario: 资料创建失败
- **WHEN** 本次注册已尝试创建账号，但对应资料创建失败
- **THEN** 注册失败，数据库中不保留本次创建的账号，也不保留本次资料

### Requirement: 账号唯一冲突与其他失败分离
系统 MUST 以数据库唯一约束裁决重复用户名，并将明确的用户名冲突呈现为稳定的注册冲突；其他数据完整性或数据库故障 MUST 继续作为失败传播，不得误报为用户名已存在。

#### Scenario: 并发注册同一用户名
- **WHEN** 两次注册竞争同一个规范化用户名
- **THEN** 至多一份账号及对应资料成功提交，另一操作得到用户名冲突，不产生第二份账号

#### Scenario: 非用户名约束失败
- **WHEN** 注册的数据访问操作发生与用户名唯一性无关的数据库失败
- **THEN** 注册失败并回滚，调用方不会收到将该故障误归类为重复用户名的结果

### Requirement: 缺失资料与空更新不产生记录
系统 MUST 区分不存在的健康资料与已经存在但未填写的资料；读取不存在的资料或对其提交空更新不得创建记录。对已有资料提交空更新 MUST 保持已保存字段和修改时间不变。

#### Scenario: 读取不存在的资料
- **WHEN** 应用调用方读取尚无资料的账号
- **THEN** 得到明确的缺失结果，数据库中仍没有该账号的资料记录

#### Scenario: 空更新不创建资料
- **WHEN** 尚无资料的账号收到没有实际提交字段的更新
- **THEN** 返回缺失结果，不创建资料记录

#### Scenario: 空更新不触碰已有资料
- **WHEN** 已有资料的账号收到没有实际提交字段的更新
- **THEN** 返回原有资料值，字段和修改时间保持不变

### Requirement: 同一账号资料更新的并发一致性
系统 MUST 保证同一账号的资料更新基于前一已提交更新后的值合并；此保证同时适用于资料已有和资料不存在的情况。并发首次填写 MUST 至多创建一份资料，不得丢弃成功操作提交的不同字段或病史键。

#### Scenario: 并发首次填写不同内容
- **WHEN** 尚无资料的同一账号并发提交两次有效更新，分别包含不同资料字段和不同病史键
- **THEN** 两次成功操作最终共同保存在唯一资料中，不产生重复资料或丢失其中一组更新

#### Scenario: 并发修改已有资料
- **WHEN** 同一账号并发修改已有资料的不同字段和不同病史键
- **THEN** 两次成功操作的字段与病史键均保留，未涉及的内容保持不变

### Requirement: 资料持久化维护审计时间
资料的实际保存操作 MUST 维护修改时间并保留原创建时间；局部更新不得清空未涉及的操作人信息或其他资料字段。

#### Scenario: 更新已有资料的一部分
- **WHEN** 已有资料完成一次包含实际字段的更新
- **THEN** 修改时间反映本次保存，创建时间不变，未提交的资料字段及未涉及的操作人信息保持原值
