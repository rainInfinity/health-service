# local-file-storage Specification

## Purpose

为原始健康输入、任务处理后文件和模型制品提供可配置的本地存储边界，确保数据库只记录受控相对存储键、未完成上传不会成为有效输入、历史文件不会因重传消失，且下载不能绕过账号与任务权限。

## Requirements

### Requirement: 文件存储键隔离于客户端路径
系统 MUST 使用服务端生成的唯一相对存储键保存上传文件，支持分别配置任务数据和模型制品根目录；不得用客户端提交的完整文件名或路径决定实际目录，不得覆盖现存输入或制品或把绝对路径公开给客户端。格式后缀 MUST 由算法契约约束。正式结果目录允许按成功发布规则替换，不允许任意覆盖。

#### Scenario: 客户端文件名包含路径
- **WHEN** 客户端上传文件名包含目录片段或绝对路径形式
- **THEN** 服务端仍生成自身的受控存储键，不按该名称访问根目录外部文件

#### Scenario: 同名上传
- **WHEN** 同一任务或不同任务上传具有相同客户端名称的文件
- **THEN** 文件各自获得独立存储键，不覆盖以前内容

### Requirement: 空文件和超限文件不得登记
系统 MUST 对上传实施明确大小上限，拒绝空文件、超限文件和中断上传；只有完整写入且数据库登记成功的文件才能成为有效输入或制品，不能把未完成文件作为当前选中记录。

#### Scenario: 上传超过上限或中断
- **WHEN** 上传文件超过配置限额，或传输／写入在完成前失败
- **THEN** 不新增有效文件记录，不改变已有选中输入，本次失败写入不能作为可下载业务文件

#### Scenario: 文件已写入但登记失败
- **WHEN** 文件完整落盘后数据库登记回滚
- **THEN** 本次新文件不获得有效业务引用，不删除以前已登记文件，系统不得声称文件与数据库是同一个原子提交

### Requirement: 读取不能逃逸存储根目录
系统 MUST 拒绝访问指向允许根目录外部的存储键，包括目录穿越和符号链接逃逸；未知或缺失文件按资源不存在处理，不通过异常暴露本地路径。

#### Scenario: 请求穿越或外部符号链接
- **WHEN** 一次业务读取解析出的文件位于配置根目录之外
- **THEN** 系统拒绝读取，不返回外部文件或绝对路径

#### Scenario: 有记录但物理文件缺失
- **WHEN** 已授权业务读取对应文件记录，但物理文件不存在
- **THEN** 系统返回安全资源不存在错误，不暴露存储根目录或底层异常正文

### Requirement: 历史输入下载遵循任务归属
系统 MUST 允许合法用户下载其当前渠道任务中已登记的当前或历史输入；重传、版本切换或任务失败不得自动删除这些历史文件。文件不属于公开静态资源，管理身份不得通过普通下载入口绕过任务归属。

#### Scenario: 重传后的历史文件
- **WHEN** 用户下载本人任务中已被新输入替代的历史文件
- **THEN** 可以按原文件记录读取历史内容，不误返回新选中文件

#### Scenario: 他人请求原始文件
- **WHEN** 未认证用户、其他账号或其他来源渠道请求下载任务文件
- **THEN** 系统按认证或资源权限边界拒绝，不暴露文件内容

### Requirement: 处理后文件仅从成功结果授权引用
系统 MUST 仅为成功任务的完整结果中明确登记的处理后文件提供按逻辑名下载，登记前验证其属于本次执行的受控输出目录；不得接受下载请求指定任意存储键，失败或失去执行权的输出不能成为权威下载内容。场景任务 MUST 只登记成功成员的文件，在 result.output_files 中使用 `<成员名>_<原逻辑名>`；失败成员即使留下物理文件也不得提供引用或下载。场景成员载荷中 MUST NOT 重复保存本地路径或另一套下载引用。

#### Scenario: 下载已登记输出
- **WHEN** 用户请求本人成功任务结果中已经登记的输出逻辑名
- **THEN** 系统返回该结果实际引用的文件，而不是重新执行算法或读取任意请求路径

#### Scenario: 访问未登记或失租输出
- **WHEN** 请求的输出未进入成功结果，或只属于失败／失租执行的目录
- **THEN** 系统拒绝下载，即使物理文件仍存在也不能据此获得访问资格

#### Scenario: 同名成员输出可独立下载
- **WHEN** PPG 场景的 HR/BR、血氧和糖尿病均成功
- **THEN** result.output_files 包含 hr_br_processed_ppg、hr_br_processed_rsp、spo2_processed_ppg、diabetes_processed_ppg，各逻辑名对应各成员本次生成的文件，不相互覆盖

#### Scenario: 失败成员没有下载能力
- **WHEN** diabetes 失败且其他成员成功，客户端请求 diabetes_processed_ppg
- **THEN** 下载按资源不存在处理，场景 result.output_files 不包含该逻辑名，也不回退到其他成员的 PPG

### Requirement: 文件成功响应不包装为 JSON
系统 MUST 在授权下载成功时返回文件内容而不是统一 JSON 业务包装；认证、权限及资源错误仍遵循既有安全错误契约。开发与部署说明 MUST 明确共享文件可达性和可能遗留孤儿文件，不自动清理既有健康数据。

#### Scenario: 文件与错误响应类型
- **WHEN** 一个合法下载成功，另一个下载因资源不存在失败
- **THEN** 前者返回实际文件内容，后者返回安全错误，不能用成功 JSON 假装已返回文件

### Requirement: 任务输入路径表达固定任务归属
新任务输入 MUST 保存为 `<channel>/<YYYYMMDD>/<YYYYMMDD_HHmmss>-<task_id>-<user_id>-<algorithm_key>-<logical_name>-<UUID>.<ext>`。渠道、用户、任务和算法 MUST 来自已授权任务；逻辑名 MUST 来自声明输入。日期和时间 MUST 来自任务创建时间并转换为 `Asia/Shanghai`，UUID MUST 是服务端生成的 32 位小写十六进制标识。

#### Scenario: 跨午夜上传和同秒重传
- **WHEN** 任务创建于上海时间 2026-11-01 23:59:59，次日上传两份同逻辑名文件
- **THEN** 两份文件均进入渠道的 `20261101/`，名称以 `20261101_235959-` 开头，包含同一任务和用户标识，使用不同 UUID 并保留历史文件

#### Scenario: 无任务记录时排查归属
- **WHEN** 任务记录丢失但新布局的原始文件与路径仍存在
- **THEN** 运维可从渠道目录和文件名辨认原任务、用户、算法与输入逻辑名；路径本身不授予下载权限，也不自动重建任务

### Requirement: 制品路径表达模型版本与逻辑用途
新制品 MUST 保存为 `<model_code>/<version>/<logical_name>-<UUID>.<ext>`，使用所属版本的模型代码和版本字符串，不加入渠道、用户或日期。各路径段 MUST 经过可逆路径编码和长度边界检查，不能产生目录穿越或静默截断碰撞；同一版本的逻辑名唯一和已发布版本不可变约束 MUST 保持。

#### Scenario: 多个版本使用同逻辑名
- **WHEN** 两个模型版本分别上传契约允许的 `spo2` 制品
- **THEN** 文件分别位于各自模型版本目录，逻辑名相同不造成文件覆盖

#### Scenario: 非法路径段
- **WHEN** 路径元数据含分隔符、保留路径片段或编码后超出支持长度
- **THEN** 服务端可逆编码合法值或以安全配置错误拒绝，不能逃逸根目录、截断或覆写其他文件

### Requirement: 上传格式后缀由声明契约约束
算法 MUST 声明每个输入和制品允许的格式后缀；上传 MUST 仅提取客户端文件名的格式后缀并归一化，与声明匹配后生成服务端文件名。缺失或不支持后缀 MUST 拒绝登记，不能静默退回 `.bin`。后缀校验 MUST NOT 代替现有内容校验或执行任意反序列化。

#### Scenario: 正式 PPG 输入
- **WHEN** PPG CSV 以 `.CSV` 后缀上传
- **THEN** 服务端以 `.csv` 保存；若内容损坏，算法仍按既有输入错误契约拒绝

#### Scenario: 血氧制品格式
- **WHEN** 血氧契约要求 `spo2` 为 ONNX、两份特征清单为 JSON
- **THEN** 分别保存为 `.onnx` 和 `.json`，将旧 pickle 清单作为 `.pkl` 上传时拒绝，不以更换文件后缀执行 pickle

### Requirement: 正式输出保持任务目录与原文件名
新正式结果 MUST 呈现为 `<channel>/<任务创建日期>/outputs/<task_id>/<算法原结果文件名>`；场景结果 MUST 在该任务目录中增加固定成员名子目录，呈现为 `<channel>/<任务创建日期>/outputs/<task_id>/<成员名>/<成员原结果文件名>`。日期与输入采用相同任务创建时间，结果名不附加输入 UUID。正式目录 MUST 只指向最近一次成功提交的完整结果集合，禁止跨根目录和未登记文件下载；失败成员的产物不得混入已发布场景目录。

#### Scenario: HR BR 双文件结果
- **WHEN** 独立 HR/BR 任务成功输出 PPG 与呼吸波形
- **THEN** 同一 `outputs/<task_id>/` 下呈现 `ppg-processed.csv` 和 `rsp-processed.csv`；跨日完成不改变任务日期目录

#### Scenario: 新成功集合替换旧集合
- **WHEN** 同一任务已有正式发布集合，且出现被运行时合法接受的新成功集合
- **THEN** 正式目录整组切换到新集合，读取不能获得新旧执行混合的文件集合；此规则不新增任务重提或成功任务自动重跑入口

#### Scenario: PPG 场景目录保留各成员原文件
- **WHEN** 三个 PPG 成员均成功并发布正式结果
- **THEN** 同一任务目录中分别存在 hr_br/ppg-processed.csv、hr_br/rsp-processed.csv、spo2/ppg-processed.csv、diabetes/ppg-processed.csv，保留各原算法 CSV 表头、时间轴与数值

#### Scenario: PPG ACC 场景目录
- **WHEN** bp 成员成功并发布正式结果
- **THEN** 同一任务目录中存在 bp/ppg-processed.csv、bp/scg-processed.csv，下载逻辑名分别为 bp_processed_ppg、bp_processed_scg

#### Scenario: 成员先写文件后失败
- **WHEN** 某成员写出临时文件后执行或结果校验失败，其他成员成功且场景即将发布
- **THEN** 失败成员产物不在正式发布目录中；若无法保证该隔离，整个场景不得提交成功或发布目录，不能只删除字典引用后将残留目录一起发布

#### Scenario: 场景全部失败无正式文件
- **WHEN** 场景正常汇总为 ALL_FAILED，成功成员文件集合为空
- **THEN** 不发布正式结果目录，不提供 output_files 引用，成员失败信息仍可从任务详情读取

### Requirement: 存量登记键继续可读取
已有数据库登记的输入、制品和成功输出相对键 MUST 继续通过通用根目录校验读取，不要求符合新命名模板。新上传 MUST 仅使用新布局，不扫描未登记文件建立业务引用，不自动移动或删除历史文件。

#### Scenario: 读取旧 bin 输入和旧执行输出
- **WHEN** 用户请求已授权的旧 `uploads/<UUID>.bin` 或旧执行目录结果
- **THEN** 返回原登记文件的字节，不推断扩展名、不改名、不改变历史任务归属

### Requirement: 场景子目录不放宽文件安全边界
场景成员文件 MUST 属于同一任务、同一执行令牌的受控目录及该成员子目录，成员名和下载逻辑名 MUST 来自固定场景声明。系统 MUST 拒绝跨成员、跨任务、跨令牌、目录穿越及符号链接逃逸的输出；不得仅因路径位于公共任务根目录内就接受。正式集合发布和恢复 MUST 沿用已有成功事务、账号及来源渠道授权规则。

#### Scenario: 成员返回其他成员文件
- **WHEN** HR/BR 成员将 spo2 子目录文件冒充其 processed_ppg
- **THEN** 输出被拒绝，不能登记为 HR/BR 的成功文件

#### Scenario: 成员输出穿越执行目录
- **WHEN** 成员返回 ../ 路径、其他令牌文件或指向执行目录外的符号链接
- **THEN** 系统拒绝该输出，不保存不可信文件引用，不向普通用户公开本地路径

#### Scenario: 版本与消息重放不重写文件
- **WHEN** 场景结果已提交，随后渠道切换或终态消息重放
- **THEN** 下载仍读取原成功结果登记的不可变文件，只允许恢复其正式发布，不重新执行成员或混用新版本产物
