# inference-algorithms Specification

## Purpose

为业务服务与独立计算建立稳定的数据和错误契约，使 service 能根据固定版本准备输入并解释结果；以正式算法实现和受控测试输入验证链路，不把未实现算法或未经临床验证的数值当作真实健康预测。

## Requirements

### Requirement: 算法契约独立于业务框架
计算接口 MUST 声明所需输入文件、制品、资料字段、参数和结果规则，只接收已准备的文件引用、固定参数及资料快照，返回完整结果、可投影值和允许的输出文件；不得依赖业务 ORM、HTTP 请求或读取实时资料。

#### Scenario: 在非 Web 环境执行
- **WHEN** 独立执行环境向合法算法提供固定输入、参数和快照
- **THEN** 算法可以按其契约执行，不需要 HTTP 请求或数据库用户资料查询

#### Scenario: 快照缺少算法必需资料
- **WHEN** 算法要求的资料字段在已提交快照中缺失
- **THEN** 计算准备阶段返回明确资料失败，不能读取实时资料或以未知默认值掩盖缺失

### Requirement: 算法注册受控且版本解释稳定
系统 MUST 仅接受受控注册且具有可执行实现的算法标识，注册元数据说明示例属性和输入输出规则；未知或未实现标识不能用于发布可执行版本。新正式算法标识 MUST 使用 `<传感器集合>.<采集模式>.<处理模式>.<输出>.v<正整数实现修订号>`，不注册无修订号或 `latest` 别名。不兼容契约或需要保留旧行为的计算规则变化 MUST 使用新实现修订，不能改变旧已发布版本的解释；仅改变既有参数值或制品且解释方式不变时允许复用实现。

#### Scenario: 使用未实现正式算法
- **WHEN** 管理人员请求发布只有接口模板而没有真实实现的正式心率／呼吸率算法
- **THEN** 系统拒绝发布，不以示例或空实现替代正式执行器

#### Scenario: 同版本历史任务解释
- **WHEN** 查询或恢复一个已提交固定版本任务，同时系统已增加其他算法版本
- **THEN** 该任务仍使用原标识的输入输出契约，不因新增算法而改变结果含义

#### Scenario: 多个实现修订同时可用
- **WHEN** 系统已注册同一算法类别的两个实现修订，两个模型发布版本分别固定引用它们
- **THEN** 每个任务按自身固定版本选择对应实现，不读取渠道当前选择或自动解析为最新修订

#### Scenario: 请求无修订号别名
- **WHEN** 新正式版本使用 `ppg.active.offline.hr_br` 或带 `latest` 的未注册别名发布
- **THEN** 发布被拒绝，不能静默替换为 `ppg.active.offline.hr_br.v1`

#### Scenario: 发布已移除的诊断标识
- **WHEN** 管理人员请求创建或发布使用 `hr_br.example` 的模型版本
- **THEN** 系统将该标识视为未注册算法并拒绝，不提供诊断执行器或将其路由到正式 PPG v1

### Requirement: 正式离线计算遵循统一的阶段与门禁
正式离线计算 MUST 按读取与校验输入、预处理、质量检测、原始推理、结果后处理、成功输出的顺序执行。质量检测和后处理 MUST 使用该固定版本的规则，不设置跨算法默认评分或范围。任一阶段失败 MUST 终止后续阶段；未执行质检不得表示质量通过。任务的输入、波形、评分、预测和输出引用 MUST 相互隔离。

#### Scenario: 质量拒绝阻止推理和成功输出
- **WHEN** 质量检测明确拒绝当前输入
- **THEN** 本次不进入推理、后处理或成功输出，也不留下可查询的成功指标或权威输出文件

#### Scenario: 后处理先于结果组织
- **WHEN** 原始预测被固定后处理规则调整
- **THEN** 完整成功结果和实际产生的投影指标均使用同一份处理后数值

#### Scenario: 相邻任务不能继承阶段数据
- **WHEN** 同一实现先后执行两个输入和输出目录不同的任务
- **THEN** 第二个任务不继承第一个任务的评分、波形、预测或文件引用

### Requirement: HR BR v1 接受明确的单块 PPG 输入
正式算法 `ppg.active.offline.hr_br.v1` MUST 要求输入逻辑名 `ppg`，不要求权重制品、健康资料或客户端元数据。CSV MUST 包含有限且严格递增的毫秒时间戳 `timestampFrame`，以及一组完整的 RGB 或 YUV 通道。每帧 MUST 只有一条记录；可选 `blockIndex` 存在时每行 MUST 为整数 `0`。输入不满足执行条件时 MUST 报告明确输入错误，不选块、不融合、不插值或补齐。

#### Scenario: 接受 RGB 和 YUV 单块记录
- **WHEN** 输入分别使用 `avgR,avgG,avgB` 或 `avgY,avgU,avgV` 的完整通道组，时间轴与数据满足单块执行条件
- **THEN** 两类输入均能进入实际计算；缺少可选帧编号、块编号或客户端元数据不单独阻止执行

#### Scenario: 明确拒绝多块数据
- **WHEN** 同一帧存在多条块记录，或存在不为整数 `0` 的 `blockIndex`
- **THEN** 算法报告 `INFERENCE.INVALID_INPUT` 和受控输入原因，不把多块行串成时间采样，也不静默选择块

#### Scenario: 输入格式或执行条件无效
- **WHEN** CSV 缺列、通道组不完整或同时提供两组通道，数值非有限，时间轴不严格递增，或数据不足以执行所需处理
- **THEN** 算法报告相应的输入错误，不伪造成功数值或默认质量结论

### Requirement: HR BR v1 基于实际输入估计两个指标
HR BR v1 MUST 依据实际输入生成心率和呼吸率估计，不用固定载荷代替计算。v1 MUST 固定所迁移的信号提取、预处理、速率估计和聚合规则，拒绝改变计算含义的未声明参数；该实现不要求模型制品或默认健康资料。正式实现身份 MUST 为非示例，但实际计算成功不表示已经完成医学准确性认证。

#### Scenario: 不同可用心率分量产生对应估计
- **WHEN** 两份满足质量条件的确定性合成输入具有不同的已知心率分量
- **THEN** 原始心率估计分别反映各自输入，并可在明确容差下与旧计算链对照，不返回同一固定心率

#### Scenario: 正式执行器可发布
- **WHEN** 模型版本引用完整 v1 key，参数与所选 HR/BR 指标契约有效，且制品集合为空
- **THEN** 版本可按既有发布规则发布，目录和任务公开 `isExample=false`，零制品不阻止执行


### Requirement: HR BR v1 使用实际 PPG 质量分数执行门禁
HR BR v1 MUST 对预处理 PPG 计算实际质量分数并使用固定阈值 `70` 比较；分数严格小于 `70` 时 MUST 以 `LOW_SCORE` 和实际比较值终止。分数等于阈值允许继续，但不保证后续估计成功。非法评分或意外异常 MUST NOT 补成零分、满分或自动解释为 `NO_VALID_SIGNAL`。

#### Scenario: 低于阈值拒绝
- **WHEN** 本次实际质量分数为 `69.999`
- **THEN** 算法报告 `LOW_SCORE`，保留 `69.999` 和 `70`，不继续估计 HR/BR

#### Scenario: 达到阈值继续
- **WHEN** 本次实际质量分数为 `70` 且其他执行条件有效
- **THEN** 质量门禁允许进入推理，后续仍须通过结果有效性检查

#### Scenario: 非法质量分数不成为质量结论
- **WHEN** 质量计算产生无法明确归因的 NaN 或无穷值
- **THEN** 算法按执行或契约错误终止，不生成成功质量信息，也不报告虚构的低分拒绝

### Requirement: HR BR v1 保留 BR 上限并拒绝非有限结果
HR BR v1 MUST 在任何范围处理前确认原始 HR 和 BR 为有限数值；任一结果为 NaN 或正负无穷时 MUST 报告 `RESULT.INVALID_OUTPUT`。有限 BR MUST 取其与 `18` 的较小值；有限 HR MUST 保留原估计，不新增限幅。v1 MUST NOT 将无效 BR 补为 `12`，也不新增下限、四舍五入或其他未声明规则。

#### Scenario: 超过 BR 上限
- **WHEN** 有限原始 HR 为 `72.5`，有限原始 BR 为 `24`
- **THEN** 完整结果为 HR `72.5`、BR `18`，对应投影值与之相同

#### Scenario: 等于或低于 BR 上限
- **WHEN** 原始 HR/BR 有限且 BR 为 `18` 或 `12.1356`
- **THEN** 对应 BR 分别保持 `18` 或 `12.1356`，HR 不受 BR 范围处理影响

#### Scenario: 非有限结果不得被截断隐藏
- **WHEN** 原始 BR 为正无穷或 NaN，或原始 HR 为非有限值
- **THEN** 计算以结果错误终止，不通过上限截断或默认值生成成功结果，不保存部分指标

### Requirement: HR BR v1 返回一致的健康指标与处理后波形
HR BR v1 的成功结果 MUST 包含有限的 `hr`、`br` 和实际质量信息；投影代码分别为 `hr`、`br`，单位分别为 `beats_per_minute`、`breaths_per_minute`。成功执行 MUST 返回逻辑名 `processed_ppg` 与 `processed_rsp` 的 CSV 文件，保留毫秒时间轴及对应处理后信号；文件引用 MUST 通过既有受保护下载链路提供，结果不暴露本地绝对路径。

#### Scenario: 成功结果和输出文件可核对
- **WHEN** 正式任务成功完成且版本选择投影 HR、BR
- **THEN** 任务详情的 HR/BR 与指标一致，两个处理后文件可由任务所有者下载，时间轴和信号行对应同一输入

#### Scenario: 不允许越权下载
- **WHEN** 其他用户或不匹配渠道请求该任务的处理后文件
- **THEN** 沿用既有任务所有权检查拒绝访问，不因正式算法新增而公开健康数据

### Requirement: 示例身份不可由客户端隐藏
系统 MUST 根据算法定义的 `isExample` 字段在可用模型、任务摘要和任务详情中公开身份；成功结果保留示例标志。客户端参数、模型名称或版本名称 MUST NOT 改变算法定义的身份。

#### Scenario: 将示例版本命名为正式版本
- **WHEN** 算法定义将 `isExample` 设置为 `true`，但模型名称不含示例标识
- **THEN** 模型及任务仍返回 `isExample=true`，名称不能掩盖非临床用途


### Requirement: 运行时复用资源不混入任务状态
系统 MUST 按固定版本复用可重复使用的计算资源，任务专属路径、资料、输出和质量状态不得保存在共享运行时实例；仍被渠道或未终结任务使用的版本资源不能因切换被错误卸载，释放实例不删除制品。

#### Scenario: 同版本多个任务
- **WHEN** 同一版本先后或并发处理两个输入和输出目录不同的任务
- **THEN** 可复用资源保持共用，但各任务输入诊断、资料和输出引用相互独立

#### Scenario: 切换后旧任务仍待执行
- **WHEN** 渠道已经切换到新版本，旧版本仍有已提交或运行任务
- **THEN** 旧任务仍可以使用旧版本资源完成；排空后卸载实例也不删除旧制品或历史结果

### Requirement: 质量拒绝以受控原因表达
独立计算契约 MUST 允许算法通过受控原因及对应的类型化明细报告质量拒绝，而不要求所有算法计算分数。首批原因 MUST 包括 `LOW_SCORE` 和 `NO_VALID_SIGNAL`；后者只表示算法依据自身明确规则确认没有可用信号，明细为 `null`。未执行质检 MUST NOT 被解释为质量通过或默认满分。

#### Scenario: 报告有评分的质量拒绝
- **WHEN** 算法实际得到分数 40、通过阈值 70，并据此拒绝继续计算
- **THEN** 拒绝原因是 `LOW_SCORE`，明细包含本次实际分数和阈值

#### Scenario: 报告不依赖评分的质量拒绝
- **WHEN** 算法依据自身明确规则判定没有可用信号，但没有计算质量分数
- **THEN** 可以报告 `NO_VALID_SIGNAL` 且明细为 `null`，不要求或补造分数与阈值

#### Scenario: 算法没有执行质量检查
- **WHEN** 一个已注册算法没有执行质量检查
- **THEN** 系统不为其生成默认质量通过、默认 100 分或虚构的质量拒绝

### Requirement: 低分拒绝使用有效的实际比较值
`LOW_SCORE` 明细 MUST 同时提供有限数值 `score` 和 `threshold`，排除布尔值、字符串、NaN 和无穷值，并满足 `score < threshold`。系统 MUST 保留实际比较值，不在比较或保存前四舍五入；量表和阈值由具体算法的固定版本定义，不设置跨算法默认阈值。

#### Scenario: 分数等于或高于阈值
- **WHEN** 试图报告分数等于或高于本次阈值的 `LOW_SCORE` 拒绝
- **THEN** 该拒绝不符合契约，不能保存成可信的低分拒绝；通过质量门槛本身也不保证后续计算成功

#### Scenario: 评分明细包含非法数值
- **WHEN** 拒绝明细缺少分数或阈值，或提供布尔值、字符串、NaN、正负无穷值
- **THEN** 该明细被视为契约错误，不以零、默认阈值或低质量结论替代

#### Scenario: 接近阈值的有效低分
- **WHEN** 算法使用实际分数 69.999 与阈值 70 比较后拒绝
- **THEN** 拒绝保留这两个原始比较值，不因展示精度将其改为相等

### Requirement: 质量拒绝不得替代输入和程序错误
算法 MUST 只在明确确认质量要求不满足时报告受控质量拒绝；文件格式不符合输入契约仍属于输入失败，未预期异常及无法明确归因的非法评分仍属于执行或契约错误。未知原因及原因与明细不匹配 MUST NOT 被默认解释为质量拒绝。

#### Scenario: 文件不符合输入契约
- **WHEN** 文件缺少规定列、时间戳无效或原始通道含非有限数值
- **THEN** 系统按输入契约报告 `INFERENCE.INVALID_INPUT`，不将这些情况自动改写成质量拒绝

#### Scenario: 质量计算发生意外异常
- **WHEN** 质量计算抛出未预期的第三方库异常，或产生无法明确归因的 NaN
- **THEN** 系统不据异常类型或异常文案推断 `NO_VALID_SIGNAL`，也不伪造低分

#### Scenario: 原因与明细不匹配
- **WHEN** 拒绝使用未知原因、为 `LOW_SCORE` 缺省明细，或为 `NO_VALID_SIGNAL` 填入评分明细
- **THEN** 该拒绝被视为契约错误，不成为可信的质量拒绝

### Requirement: 首个质量拒绝终止本次计算
算法执行 MUST 在报告首个明确质量拒绝后终止本次计算，不继续预测或生成成功结果，也不为收集更多原因而继续执行后续检查。质量拒绝仅说明触发终止的原因，不代表已完成所有输入的质量评价。

#### Scenario: 预测前明确拒绝
- **WHEN** 算法在预测前报告一个合法质量拒绝
- **THEN** 本次执行不再进入预测或后续检查，不返回部分成功结果

### Requirement: 算法可选择读取可选客户端元数据
系统 MAY 将任务提交时冻结的客户端元数据作为可选推理输入提供给算法。客户端元数据缺失 MUST NOT 被视为缺少必需健康资料，也 MUST NOT 单独阻止未依赖该元数据的算法执行；依赖特定键的算法 MUST 在自身稳定契约中定义该键的用途、类型校验及缺失时行为。

#### Scenario: 算法不依赖客户端元数据
- **WHEN** 任务未提交客户端元数据，或当前算法不读取该数据
- **THEN** 算法仍可按文件、固定参数和健康资料契约执行，缺失元数据不触发必需资料失败

#### Scenario: 算法读取已冻结元数据
- **WHEN** 已注册算法声明读取客户端元数据中的特定键，且任务提交时保存了该键
- **THEN** 算法获得该任务提交时冻结的值，而不是实时请求、用户资料或后续任务数据

#### Scenario: 算法遇到缺失或不合法的可选键
- **WHEN** 算法声明使用的可选键缺失或类型不符合其契约
- **THEN** 算法按自身声明的缺失行为处理，并拒绝不符合该键类型的值；不得假设客户端数据可信或用其绕过访问控制
