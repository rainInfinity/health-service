# inference-runtime Specification

## Purpose

为已提交推理任务提供可恢复的消息投递和独立执行契约，使暂时消息故障、进程退出和重复投递不会静默遗失待执行任务或覆盖已保存结果，同时明确有限执行次数、租约所有权和失败信息的安全边界。

## Requirements

### Requirement: 持久化待执行任务可以补偿投递
系统 MUST 在提交持久化后尝试发送只包含任务标识的消息，并持续有界扫描未发布或超过补发间隔的已提交任务及过期执行任务；成功发布时间只能在消息发布成功后记录，发布失败不得消除补发资格。

#### Scenario: 数据库提交后发布失败
- **WHEN** 已提交任务的首次消息发送失败，随后消息服务恢复且后台扫描运行
- **THEN** 该任务被重新发送并可执行，不依赖用户重新提交

#### Scenario: 发布成功后记录时间失败
- **WHEN** 消息已发送成功但成功发布时间未能持久化
- **THEN** 后续扫描可以再次发送同一任务，重复消息不能造成重复终态或丢失执行资格

#### Scenario: 过期执行任务没有可重领条目
- **WHEN** 任务执行租约已经过期，但后台没有可直接重领的原消息
- **THEN** 数据库补发扫描仍能重新发送该未终结任务，不能只因原消息缺席永久跳过

### Requirement: 执行领取具有可过期所有权
系统 MUST 只允许领取已提交或执行租约已过期的任务，每次有效领取分配新的执行所有权令牌并增加一次尝试次数；重复消息和未成功领取不得增加次数。仍有有效租约的任务不得再次执行。

#### Scenario: 两个消息并发领取同一任务
- **WHEN** 两个执行者同时处理同一任务的重复消息
- **THEN** 至多一个获得当前有效执行权，另一个不能启动重复业务计算或增加尝试次数

#### Scenario: 进程退出后重领
- **WHEN** 执行进程退出，任务仍运行中且租约到期
- **THEN** 新执行者可以取得新令牌继续处理，保留固定版本、输入快照和首次开始时间

### Requirement: 心跳维持健康长任务的租约
系统 MUST 在正常执行期间周期性续约，续约要求当前令牌匹配且租约仍有效；过期令牌不得通过迟到心跳重新获得所有权。租约时间判定 MUST 不依赖执行者之间未同步的本地时钟。

#### Scenario: 长计算保持活跃
- **WHEN** 合法执行持续超过初始租约长度且心跳正常
- **THEN** 租约持续有效，其他执行者不能仅因消息空闲时间重新取得该任务的执行权

#### Scenario: 迟到续约
- **WHEN** 原执行者在租约已经过期或新执行者已取得任务后发送心跳
- **THEN** 续约被拒绝，不延长旧执行权或撤销新执行者所有权

### Requirement: 失去执行权不能写入终态
系统 MUST 仅允许持有当前匹配令牌且租约未过期的执行者提交成功或失败；失租执行的计算输出不得覆盖恢复后结果，也不得确认仍需新执行者处理的消息。

#### Scenario: 旧执行晚于恢复完成
- **WHEN** 原执行者失租后继续计算，新执行者已完成任务，原执行者再尝试落库
- **THEN** 原执行写入被拒绝，已保存完整结果、投影和终态保持不变

#### Scenario: 原执行在恢复前迟到
- **WHEN** 租约已经过期但尚无新执行者，原执行者尝试保存结果
- **THEN** 系统仍拒绝其过期执行权写入，不能通过抢先落库复活旧租约

### Requirement: 有限重领次数不混淆基础设施故障
系统 MUST 对执行领取次数设置上限；达到上限且租约过期的未终结任务记录 `TASK.RETRY_EXHAUSTED` 和完成时间。数据库或消息服务的暂时故障不得仅因异常出现就直接映射为算法失败或业务终态。

#### Scenario: 执行持续退出达到上限
- **WHEN** 一个任务已经历允许次数的有效领取，最后一次执行仍未终结且租约过期
- **THEN** 恢复流程将其记为重领次数耗尽，不再次启动计算，也不生成成功结果或指标

#### Scenario: 消息确认暂时失败
- **WHEN** 成功结果已经持久化，而消息确认遭遇暂时连接错误
- **THEN** 任务保持成功，不能改写为失败；后续重放消息只执行确认

### Requirement: 成功结果和指标原子保存
系统 MUST 按任务固定版本校验完整输出，并在同一持久化事务保存完整结果、实际存在且选定的投影指标以及成功状态和完成时间；未产生的指标不写行。数值必须有限，布尔与数值类型不得混淆，失败不能留下部分成功投影。

#### Scenario: 合法结果包含部分指标
- **WHEN** 合法完整输出只产生该版本允许投影指标中的一部分
- **THEN** 完整输出保存为权威结果，只保存实际产生且类型正确的投影，其他指标不以零或 false 补齐

#### Scenario: 指标保存中断
- **WHEN** 成功写入事务在保存结果或投影时发生数据库错误
- **THEN** 整个事务回滚，不留下成功状态与结果／投影不一致的数据，不确认该消息

#### Scenario: 输出或投影无效
- **WHEN** 算法输出结构无效，或产生与选定指标不符的类型、非有限数值
- **THEN** 当前有效执行记录 `RESULT.INVALID_OUTPUT`，不保存成功结果或部分指标

### Requirement: 失败来源与公开信息安全
系统 MUST 用 `TASK.*`、`INFERENCE.*`、`RESULT.*` 区分任务流程、计算和输出失败，并与完成时间同事务保存；摘要必须可安全公开，诊断不得包含原始健康数据、堆栈、绝对路径或任意异常正文。

#### Scenario: 输入内容或所需资料无效
- **WHEN** 执行前发现文件内容不符合固定契约，或快照缺少该算法必需资料
- **THEN** 当前执行以明确计算失败代码终结，不从实时资料补值、不伪造健康结果

#### Scenario: 算法发生意外异常
- **WHEN** 当前合法执行中的计算代码发生未预期异常
- **THEN** 系统记录安全执行失败代码和固定摘要，不将异常正文写入数据库或普通日志

### Requirement: 终态持久化后才确认消息
系统 MUST 只在任务终态持久化、已经观察到持久化终态或确认消息不可执行后确认消息；重复终态消息不能再次执行或修改结果。暂未取得执行权的非终态任务消息必须保留恢复机会。

#### Scenario: 落库后确认前进程退出
- **WHEN** 成功或失败事务已提交，执行进程在消息确认前退出
- **THEN** 消息重领后只确认已有终态，不重复写入或重新执行

#### Scenario: 有效租约被其他执行者持有
- **WHEN** 消费者重领消息但数据库任务仍由另一有效租约持有
- **THEN** 消费者不执行、不确认该非终态消息，稍后仍能恢复处理

#### Scenario: 不可执行消息
- **WHEN** 消息引用不存在任务或任务标识格式无效
- **THEN** 消费者安全确认该条消息，不生成假任务、结果或敏感异常记录

### Requirement: 独立消费可运行且退出可恢复
系统 MUST 提供独立于 Web 的常驻消费入口及单轮运行模式，完成补发、领取、执行和确认；退出时停止新领取，不把未完成任务伪装为终态。消息保留策略不得丢弃仍需恢复的未确认任务。

#### Scenario: 单轮处理示例任务
- **WHEN** 运行单轮模式且存在已提交的合法示例任务
- **THEN** 入口实际完成本轮有界派发和消费，保存明确示例结果；无消息时能退出而非永久等待

#### Scenario: 执行中停止进程
- **WHEN** 消费者在完成终态前退出
- **THEN** 未确认消息与数据库执行信息保留，租约过期后新消费者可以恢复该任务
